# 보스 레이저 개선 — 2026-10-21

후속 피드백으로 고정 각도·속도 14·삼각형 안전 구역·벽 재진입 방식으로 변경되었습니다. 현재 동작은 `BossLaserWallPatternNotes.md`를 참고하세요. 아래는 이전 구현 기록입니다.

## 적용 범위와 결과

수정은 `Assets/CTJ` 안에서만 진행했습니다. 공용 모듈, 플레이어, 다른 동료 폴더, 패키지 설정은 수정하지 않았고 패키지를 설치하지 않았습니다. 기존 보스 FSM·스킬 등록·지정 스킬 진입점을 그대로 사용합니다.

| --- | --- | --- |

일반 이동 속도 4, 플레이어 위치로 이동하는 속도 8, 가감속 시간 0.2초는 유지합니다. 원형 탄막의 준비 시간도 바꾸지 않았습니다. HP 1000 이하 1회 발동, 편도 3회, 횡단당 최대 1회 피해, 중앙 복귀 및 무적 해제 규칙도 유지합니다.

보스의 횡단 끝점은 해당 위험 구역 안쪽입니다. 안전 구역으로 넘어가 빔이 잘려 없어지는 시간을 만들지 않도록 했습니다. 매 횡단 경고 시작 시 안전 구역이 교대하며, 발사 중에는 고정됩니다.

## 책임 분리

- `BossArenaModule`: 안전 비율과 위험 구역 Bounds, 이동 시작점·끝점만 계산합니다.
- `RobotEyeBoss`: 준비 위치 이동, 지정 레이저 스킬 실행, 횡단·복귀 순서를 담당합니다.
- `BossLaserSkill`: 경고, 회전 빔의 표시·판정, 횡단당 피해 중복 방지를 담당합니다. 실제 판정은 경고와 같은 위험 구역 안에 제한합니다.
- `BossLaserShake`: 기존 Cinemachine 임펄스 시스템에 발사 중 신호를 보내고 끝나면 자기 신호만 취소합니다. 카메라 추적 코드를 직접 수정하지 않습니다.
- `BossLaserDelay.asset`: 레이저 준비 시간의 StatData 키입니다. 실제 값은 `RobotEye_Stats.asset`의 해당 항목에서 조절합니다. 공통 준비 스탯과 분리했으므로 원형 탄막에 영향을 주지 않습니다.

새로운 인터페이스나 추상 클래스는 만들지 않았습니다. `BossLaserShake`는 기존 `MovingLaser` 오브젝트의 부가 효과 컴포넌트이며, ModuleOwner의 모듈 수는 기존 8개 그대로입니다.

### 카메라 연결

이미 설치된 Cinemachine을 사용했습니다. CTJ_MapTestScene의 Main Camera, BossPatternTest의 Boss Test Camera에 `CinemachineExternalImpulseListener`를 추가했습니다.

- Channel Mask: 숫자 64, 즉 7번째 채널 비트. 이 레이저 전용 채널입니다.
- Gain: 1, Use 2D Distance: 켬, Use Local Space: 끔.
- 추가 잔진동은 끕니다. 경고 대기 중에는 흔들지 않고, 발사 종료·취소·타깃 유실·비활성화 시 중단합니다.
- 다른 씬에서도 사용하려면 실제 출력 Camera에 같은 Listener를 설정해야 합니다. 보스가 모든 씬의 카메라를 자동 수정하지는 않습니다.
- 단순 카메라에서 실제 흔들림·원위치 복구를 런타임 검증했습니다. PlayerPack을 포함한 실제 방의 카메라 연동·최종 체감은 아래 수동 테스트에서 확인합니다.

## 피해 판정과 대쉬 관련 주의

경고 사각형 전체가 즉시 피해를 주는 것은 아닙니다. **경고는 이번 횡단의 위험 영역이고, 피해는 실제로 회전하는 빔이 접촉했을 때** 전달합니다. 빔 두께까지 포함해 경고 밖으로 나가지 않도록 자릅니다.

고속 이동으로 빔이 타깃을 건너뛰지 않도록 이전 틱과 현재 틱 사이의 위치·각도도 여러 번 검사합니다. 회전 빔을 둘러싼 큰 AABB 전체로 피해를 주지 않습니다. 타깃의 여러 콜라이더에 닿거나 반복 접촉해도 한 횡단에서 피해 전달은 최대 1회입니다.

완전히 안전 구역 안에 들어온 콜라이더는 해당 횡단에서 맞지 않습니다. 몸 일부가 위험 구역에 걸치면 맞을 수 있습니다.

**현재 로컬 PlayerController/PlayerDasher/DashState에서는 대쉬 중 피해를 차단하는 무적 조건을 확인하지 못했습니다.** 이번 작업은 플레이어 코드를 수정하지 않았으며 기존 IDamageable 경로로 전달합니다. 따라서 대쉬 무적 회피가 보장된다고 판단하면 안 됩니다. 실제 PlayerPack의 피해 수신 측에서 무적 처리를 담당하도록 동료와 확인해야 합니다. BossPatternTest의 더미에도 대쉬 기능은 없습니다.

## 직접 테스트하는 순서

### 전용 테스트 씬

1. 작업 중인 씬을 저장한 뒤 `Assets/CTJ/Prototypes/Bosses/BossPatternTest.unity`를 열고 Play합니다.
2. 왼쪽 위 `Deal 1500 damage (2500 -> 1000)` 버튼을 한 번 누릅니다. 레이저 패턴은 보스 한 마리당 한 번만 발동하므로 반복 테스트는 Stop → Play로 시작합니다.
3. 보스가 빠르게 준비 위치로 이동하는지 확인합니다. 경고가 약 0.4초 나온 뒤 발사와 빠른 이동이 시작되어야 합니다. 출발·도착 때의 가감속은 유지됩니다.
4. 안전 구역이 **오른쪽 → 왼쪽 → 오른쪽**으로 바뀌는지 확인합니다. A/D 또는 방향키로 더미를 움직입니다. Space는 점프입니다.
5. 빨간 영역은 위험 구역 전체이고 안전 구역은 비어 있어야 합니다. 발사 중에도 영역 표시가 유지되고 대각선 레이저가 각도를 바꾸며 훑어야 합니다.
6. 안전 구역 안에 몸 전체가 있으면 `Target hits`가 증가하지 않아야 합니다. 위험 구역에서 빔에 닿으면 30 피해가 추가되며, 한 횡단에서 여러 번 닿아도 최대 1회여야 합니다.
7. 발사 중에만 강하게 흔들리고, 횡단 사이의 대기·패턴 종료 뒤에는 멈춰야 합니다. 3회 후 중앙 복귀, 무적 해제, 일반 패턴 재개를 확인합니다.
8. 다음 Play에서 BossLaserShake를 꺼 비교합니다. 흔들림만 사라지고 공격은 유지되어야 합니다. 준비/발사 중 보스를 비활성화해도 빔·경고·쉐이크가 남지 않아야 합니다.

기본값은 속도감을 높인 첫 튜닝입니다. 교대 안전 구역까지 이동하는 난도는 실제 플레이어 속도와 대쉬 무적 연동 뒤 다시 플레이하며 조절해야 합니다.

### 실제 플레이어와 맵

1. CTJ_MapTestScene의 Main Camera에 External Impulse Listener가 활성화되어 있는지 확인합니다.
2. RobotEyeBoss 프리팹을 테스트 위치에 놓고, ArenaModule의 Center/Floor/Width가 실제 방과 맞는지 확인합니다. 보스 생성 위치가 기본 아레나 중심입니다.
3. 플레이어를 Target에 연결하거나 기존 지연 연결 경로를 사용합니다. HP를 1000 이하로 낮추되, 즉시 죽이는 피해를 주면 안 됩니다.
4. 실제 카메라 추적 중 쉐이크, 안전 구역 회피, 기존 플레이어 피해 처리와의 연동을 확인합니다. 대쉬 무적은 별도 확인 항목입니다.

## 사용한 문법과 이유 — 학습 메모

### readonly struct

`BeamPose`는 한 시점의 중심·크기·방향·각도를 묶는 작은 값 형식입니다. `readonly`로 계산 후 내부 값을 바꾸지 못하게 했습니다. 표시와 판정이 같은 계산 결과를 사용하도록 돕고, 촘촘한 중간 판정마다 관리 힙에 새 객체를 만들 필요가 없습니다.

### ref 매개변수

`ClipAxis(..., ref near, ref far)`는 X축/Y축 제한을 계산하면서 같은 시작·끝 거리를 갱신합니다. 일반 float 매개변수는 값 복사라 메서드 안에서 바꿔도 호출자의 값이 바뀌지 않지만, `ref`는 호출자가 가진 변수에 계산 결과를 반영합니다. 두 축의 유효 구간이 겹치는 부분만 남기는 방식입니다.

### Bounds, 벡터와 회전 사각형

`Bounds`는 축에 평행한 아레나 영역을 표현합니다. 빔 방향의 수직 벡터 `(-y, x)`로 두께가 차지하는 여유 폭을 계산하고, 중심선의 사용 가능 영역을 줄였습니다. `Mathf.Atan2`로 빔 각도를 구해 `Physics2D.OverlapBox(center, size, angle, ...)`와 시각 요소에 같은 각도를 전달합니다.

### Mathf.Pow, Lerp와 진행 비율

이동 경로의 진행률 t에 `Mathf.Pow(t, sweepLag)`를 적용하면 0~1의 중간 값이 작아집니다. 예를 들어 t=0.5, 지수=2이면 0.25입니다. 보스가 절반 이동했을 때 바닥 조준점은 1/4 지점에 있으므로 빔이 비스듬해집니다. `Lerp`는 이 진행률을 실제 위치로 바꿉니다.

### 기존 인터페이스 구현과 out

`LaserSignal : ISignalSource6D`는 Cinemachine에 이미 있는 신호 인터페이스를 구현한 것입니다. 새 프로젝트 공용 인터페이스를 만든 것이 아닙니다. `GetSignal(..., out Vector3 pos, out Quaternion rot)`의 `out`은 위치와 회전 두 결과를 함께 돌려주기 위한 문법이며, 메서드 안에서 반드시 값을 지정합니다. 이번 효과는 XY 위치만 흔들고 회전은 identity로 유지합니다.

### ReferenceEquals와 생명주기 정리

임펄스 이벤트는 Cinemachine이 재사용할 수 있으므로 `ReferenceEquals`로 현재 이벤트의 신호가 내가 만든 신호인지 확인한 뒤 취소합니다. 스킬 종료/중단과 OnDisable에서 정리하며 다른 임펄스 전체를 지우지 않습니다. 같은 프레임에 발사와 취소가 겹쳐도 신호를 제거하고, 라이브러리가 이벤트를 회수할 수 있는 최소 양수 수명을 남깁니다.

`?.`는 참조가 null이면 호출을 생략하는 문법입니다. 효과 컴포넌트가 없어도 공격이 작동하도록 `cameraShake?.StartShake(...)` / `StopShake()`를 사용했습니다.
