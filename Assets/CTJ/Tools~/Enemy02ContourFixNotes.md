# Enemy02 — 바깥과 맞닿는 전체 경계선 수정

2026-10-28. 작업 범위는 Assets/CTJ입니다.

## 무엇을 고쳤는가

몸통·런처·지면 받침을 합친 모양에서 외부에 노출된 위·아래·좌·우 경계를 모두 표시합니다. 몸통 안쪽 장식이나 런처와 몸통이 겹친 내부에는 선을 표시하지 않습니다. 평소 짙은 붉은색, 피격 시 흰색이라는 기존 설정은 유지했습니다.

두 가지 원인을 확인했습니다.

1. **맵 위치에 따라 선이 빠짐:** 셰이더는 스프라이트의 로컬 좌표로 꼭짓점을 확장했는데, 동적 배칭 과정에서 좌표가 월드 기준으로 합쳐지면서 확장 방향이 틀어졌습니다. 원점에서는 일부가 맞아 보였지만, 위치를 옮기거나 런처를 왼쪽으로 돌리면 큰 부분이 사라졌습니다.
2. **받침 아래쪽 선이 잘림:** 지면 아래로 숨기는 SpriteMask가 지면에 고정된 GroundRim의 외곽선까지 잘랐습니다. 몸통·런처의 수납 마스크는 유지하고, 수납되지 않는 GroundRim만 Mask Interaction을 None으로 바꿨습니다. 받침 원본은 원래 지면 위에 있어 몸체 모양은 달라지지 않습니다.

추가로 Width를 크게 설정하면 얇은 받침을 건너뛰어 선이 비는 문제가 있어, 가까운 픽셀부터 지정 두께까지 검사하도록 보완했습니다. 대각선으로 확장한 선이 메쉬 끝에서 잘리지 않도록 여유 공간도 늘렸습니다.

## 변경 파일과 조절 위치

- `Shaders/EnemyOutline.shader`: 로컬 좌표를 보존하도록 동적 배칭 제외, 연속적인 바깥 알파 검사, 대각선 확장 여유.
- `Prototypes/Prefabs/Enemy02_ProjectileRobot.prefab`: `Visual/GroundRim`의 SpriteRenderer → Mask Interaction = None.
- `Tools~/ConfigureEnemyArtRefresh.cs`: 다시 구성해도 받침 마스크 설정을 유지하도록 반영.
- `Tools~/VerifyEnemyOuterContour.cs`: 외곽 전체에 빠진 픽셀이 있는지 검사하는 재현·회귀 검증.

기존 `OutlineModule → EnemyOutlineModule`의 `Width`, `Normal Color`, `Hit Color`, `Hit Duration`으로 외형을 조절합니다. 기본 Width 2와 색상은 이번에 변경하지 않았습니다. `Outer Silhouette Only`는 켠 상태로 사용합니다.

## 직접 테스트

1. CTJ_MapTestScene을 Play하고 Enemy02의 공격 범위 안팎으로 이동합니다.
2. 플레이어가 적의 왼쪽·오른쪽·위쪽으로 이동하여 런처를 회전시킵니다. 포신 끝과 아래쪽, 몸통 양옆, 지면 받침 아래까지 테두리가 이어져야 합니다.
3. 공격 범위를 벗어나 수납될 때에도 보이는 몸통과 받침의 외곽선이 이어지는지 확인합니다. 땅 밑에 숨은 몸통·런처는 계속 숨겨집니다.
4. 적을 때리면 같은 외곽선이 잠시 흰색이 되고 돌아와야 합니다. 내부 장식/파츠 경계에는 선이 생기지 않아야 합니다.
5. 더 굵게 보고 싶다면 Play 중 Width를 2~6 사이로 바꿔 확인합니다. 원하는 값을 유지하려면 Play 종료 후 프리팹에 적용합니다.

## 검증 결과

기존 코드에서 144×96 렌더링으로 재현했을 때, 원점 오른쪽 조준은 외부 인접 픽셀 217개 중 69개, 다른 위치 왼쪽 조준은 217개 중 177개의 선이 빠졌습니다. 좌표 문제만 수정하면 아래쪽 받침에서 48개가 남았고, 받침 마스크 수정 후 0개가 되었습니다.

최종 검증은 원점 / 양수 좌표 / 음수 좌표, 오른쪽 / 왼쪽 / 대각선 / 아래 조준, 수납, 좌우 반전과 비균일 스케일, Width 2·6을 포함한 8가지입니다. **모두 외곽 인접 픽셀 누락 0개, 내부 파츠 변경 0개**를 확인했습니다.

720×480의 추가 렌더링에서도 0° / 45° / -90° 조준의 내부 변경은 0개였습니다. 피격 흰색·수납 모습은 실제 URP 렌더링으로 확인했습니다. 셰이더 컴파일 오류와 변경 프리팹 참조 누락도 검사했습니다.

이전 검증은 외곽선이 일부라도 나타나는지와 내부 선 제거를 확인했으며, 외곽 전체 연속성을 확인하지 못했습니다. 새 검증은 원본 실루엣 주변의 각 픽셀을 확인하여 같은 누락을 검출합니다.

## 사용한 문법과 이유 — 학습용

### DisableBatching

ShaderLab의 `Tags { "DisableBatching"="True" }`는 해당 셰이더를 동적 배칭에서 제외하는 설정입니다. 원본 메쉬의 로컬 좌표를 기준으로 변형하는 이번 셰이더에서 좌표가 미리 월드 좌표로 합쳐지는 것을 방지합니다. C#이나 프로젝트 전체의 배칭 설정을 바꾸지는 않습니다. 대신 이 임시 아웃라인 셰이더에는 동적 배칭 최적화가 적용되지 않습니다.

Unity 공식 설명: [Disable dynamic batching of a shader](https://docs.unity.cn/Manual/writing-shader-tags-disable-dynamic-batching.html).

### SpriteMaskInteraction.None

SpriteRenderer의 `maskInteraction`은 열거형(enum)입니다. `None`은 마스크로 자르지 않는다는 뜻입니다. 수납되는 몸통/런처와 고정 받침의 역할이 달라 받침에만 지정했습니다. 아웃라인 모듈은 원본 렌더러의 이 설정을 따라갑니다.

### ceil과 for 반복문

`ceil(width)`는 소수 두께를 올림해 필요한 검사 횟수를 구합니다. HLSL의 `for`로 1픽셀부터 지정 폭까지 주변 알파를 검사합니다. 최대 거리만 한 번 검사하면 가는 파츠를 넘어갈 수 있지만, 중간 거리도 확인하면 경계 바로 옆부터 선을 채울 수 있습니다. `[loop]`는 셰이더 컴파일러에 반복문 형태로 처리하도록 주는 힌트입니다. 기본 Width 2에서는 두 단계만 검사합니다.

`max`로 주변의 불투명 값을 모으고 `(1 - centerAlpha)`를 곱하여 원본 바깥만 남깁니다. 그 결과를 원본 파츠 뒤에 그려 내부 경계는 가려지게 합니다.
