# 코인 바운스와 소멸 애니메이션

2026-10-29. Assets/CTJ 안에서만 수정했습니다. 기존 즉시 지급 코드 백업은 그대로 보존했습니다.

## 현재 동작

사망 → 회전하면서 흩어짐 → 바닥에서 작게 두 번 튐 → 바닥에서 소멸 애니메이션 → Gold 지급.

첫 바운스는 위로 속도를 주고 중력으로 다시 내려옵니다. 두 번째는 초기 속도를 55%로 줄여 더 낮게 튑니다. 바운스가 끝나면 그 위치에서 gold_collect의 6프레임을 한 번 재생합니다. Renderer의 알파를 낮추거나 코인을 위쪽 위치로 보간하지 않습니다. 소멸 마지막 프레임의 표시 시간까지 지난 후 담당 금액을 한 번 지급합니다.

## 인스펙터 조절

`Prototypes/Prefabs/EnemyRewardCoin.prefab`의 **EnemyRewardCoin**에서 조절합니다.

| 필드 | 기본값 | 용도 |
| --- | --- | --- |
| Max Bounces | 2 | 바닥에서 튀는 횟수. 0이면 첫 착지 때 소멸 연출 시작 |
| Bounce Speed | 2.6 | 첫 바운스의 초기 속도. 높이와 공중 체류 시간에 영향 |
| Bounce Damping | 0.55 | 다음 바운스의 속도 배율. 0.55면 두 번째 속도는 첫 번째의 55% |
| Horizontal Retention | 0.65 | 착지 후 표면을 따라 유지할 속도 배율. 평지에서는 좌우 속도가 줄어듦 |
| Spin Frames | gold_spin 7장 | 비행/바운스 중 반복할 회전 프레임 |
| Spin Frames Per Second | 12 | 회전 애니메이션 속도 |
| Collect Frames | gold_collect 6장 | 한 번 재생할 소멸 프레임 |
| Collect Frames Per Second | 12 | 소멸 속도. 현재 6÷12=0.5초 후 지급 |
| Gravity Scale | 1.5 | 초기 낙하와 바운스 모두에 적용되는 중력 배율 |
| Max Air Time | 3초 | 바닥을 못 찾으면 소멸로 넘어갈 제한 시간. 바운스할 때 다시 시작 |

기존 Horizontal Speed / Upward Speed Range는 처음 흩뿌릴 때의 속도입니다. 바운스 강도를 바꾸려면 Bounce Speed를 조절하세요. 프리팹의 표시 크기는 Transform Scale 1.2, 충돌 검사 반지름은 0.115입니다. 새 스프라이트가 기존 것과 PPU가 달라 Scale 값은 커졌지만 실제 코인 높이는 약 0.22 월드 단위로 작게 유지했습니다.

각 적의 `CurrencyRewardModule → Currency Per Coin`은 **3**으로 바꿨습니다. Max Coin Count는 기존 **12**를 유지합니다. 기준값은 코인 개수를 정하며, 실제 지급은 총액을 균등 분배하고 남은 골드를 1씩 나눕니다.

| 총 보상 | 코인 수 | 코인별 금액 |
| --- | --- | --- |
| 3 | 1 | 3 |
| 4 | 2 | 2, 2 |
| 7 | 3 | 3, 2, 2 |
| 10 | 4 | 3, 3, 2, 2 |
| 15 | 5 | 각각 3 |
| 37 | 12 | 4 하나 + 3 열한 개 |

총 보상 스탯은 변경하지 않았습니다. 따라서 Enemy01/Enemy04/Catto는 10골드에 코인 4개, Enemy02/MadGhost는 15골드에 코인 5개입니다. 보스는 기존 보상값 0입니다.

## 스프라이트 연결

`Assets/CTJ/Assets/Animated Gold Coin - Free/Gold`의 원본 PNG를 사용합니다. 회전은 175×25, 소멸은 150×25이므로 각각 25×25로 7장/6장 분리했습니다. 기존 자동 분할에서는 소멸 끝 3장이 한 프레임에 합쳐져 있어 이 부분도 정리했습니다. 피벗은 모든 프레임의 중앙으로 통일하고 Point 필터와 무압축을 적용했습니다. 원본 PNG와 기존 스프라이트 식별자는 보존했습니다.

프리팹의 배열에 프레임 순서대로 연결되어 있으며 별도 Animator Controller는 사용하지 않습니다. 현재 필요한 두 애니메이션은 SpriteRenderer.sprite를 교체하는 방식으로 처리합니다. 이 방법에서는 FPS와 프레임 수가 소멸 시간의 기준이라, 지급 타이밍을 별도 애니메이션 이벤트와 맞출 필요가 없습니다.

## 직접 테스트

2. Enemy01을 처치합니다. 코인 4개가 회전하며 흩어지고, 바닥에서 두 번 낮게 튀는지 확인합니다.
3. 두 번째 바운스가 더 낮으며 다시 바닥에 내려온 뒤 반짝이는 소멸 연출이 나오는지 확인합니다. 알파 페이드나 떠오르며 정지하는 움직임은 없어야 합니다.
4. 각 코인의 소멸 연출 종료에 맞춰 Gold가 증가하고, 최종 합계가 10인지 확인합니다. Enemy02는 코인 5개, 합계 15입니다.
5. 바운스 느낌을 바꾸려면 Play 중 생성된 코인의 Bounce Speed 등을 바꿔 비교합니다. 영구 적용은 Play 종료 후 코인 프리팹에서 설정하세요.

VerifyEnemyCoinReward.RunEdit / RunPlay로 참조, 금액 경계, 반복 지급 방지, 실제 상승·하강, 6개 소멸 프레임, 지형, 씬 정리 정산을 확인합니다. 기존 독립 씬 테스트 절차(BeginPlay → RunPlay → StopPlay → RestoreScene)를 사용합니다. 기존 보상 유실 방지와 적의 수명에서 독립된 코인 수명도 유지합니다.

이번 확인 결과: Unity 컴파일 오류 0건. 여섯 적의 연결, 3골드 기준 경계값(3/4/6/7골드 등), 12개 상한, 실제 바운스의 상승·하강, 알파값 유지, 소멸 6프레임 표시, 완료 후 정확한 금액 지급, 일방향 발판/벽/얇은 바닥/트리거, 바닥 없는 경우, 씬 언로드 정산을 모두 통과했습니다. 새 스프라이트의 산개·바운스·소멸 렌더링을 확인하고 임시 캡처는 삭제했습니다. 원래 씬과 즉시 지급 백업의 파일 해시는 변경되지 않았습니다.

## 사용 문법과 이유

- **`Sprite[]`**: 애니메이션 프레임을 순서 있는 배열로 저장합니다. `[SerializeField]`이므로 인스펙터에서 이미지를 교체할 수 있습니다.
- **`FloorToInt(경과 시간 × FPS)`**: 현재 표시할 프레임 번호를 계산합니다. 회전은 `% 프레임 수`로 반복하고, 소멸은 프레임 수에 도달하면 완료합니다.
- **`Mathf.Pow(감쇠율, 바운스 횟수)`**: 첫 속도는 그대로, 다음부터 감쇠율을 반복 적용합니다. 기본값에서는 2.6 → 1.43으로 줄어듭니다.
- **`Vector2.Dot`와 표면 법선**: 충돌 전 속도 중 바닥 안쪽으로 향하는 부분을 제거하고, 표면을 따라가는 속도와 튀어나가는 속도로 나눕니다. 벽 접촉 처리는 기존대로 유지합니다.
- **`FixedUpdate`의 중력 적분**: 튕긴 뒤에도 중력을 계속 적용하므로 올라가다 느려지고 다시 떨어집니다. 위치를 위로만 보간하던 방식과 달라진 부분입니다.
- **`BounceCount` / `IsCollecting` 읽기 전용 프로퍼티**: 외부에서는 진행 상태를 확인할 수 있고, 변경은 코인 내부에서만 하도록 `private set`을 사용했습니다.
- **프레임별 동일한 Rect·Pivot**: 소멸 조각이 줄어들어도 객체의 기준 위치는 같아 스프라이트가 옆으로 튀지 않습니다. Unity의 기존 Sprite Data Provider API로 임포트 설정만 정리했습니다.
