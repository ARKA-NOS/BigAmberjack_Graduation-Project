# 보스 레이저: 벽 대기·고정 대각선·화면 밖 복귀

> 2026-10-28 정리: 아래에 언급된 일회성 생성 도구·과거 검증 파일·캡처 일부는 삭제되었습니다. 설명과 검증 결과는 당시 작업 기록입니다. 현재 남긴 도구는 [README.md](README.md)를 확인하세요.

2026-10-21 후속 피드백 반영. 이전 BossLaserFeedbackNotes의 회전 빔/세로 안전 띠 설정은 이 문서의 고정 각도/삼각형 안전 구역으로 대체합니다. 현재 조절값은 아래 표를 기준으로 확인하세요.

추가 피드백 반영: 도착 벽에서 감속하지 않고 화면 밖까지 연속 이동, 시각 빔 길이 18유닛 고정, 레이저 경고 알파 50→25. 이후 재공격/중앙 복귀 간격 단축도 반영했습니다. 발사 속도는 프리팹 20, 테스트 씬 오버라이드 50을 유지하고, 일반 이동의 가감속 1초와 레이저 전용 가감속 0.2초를 분리했습니다.

## 현재 동작

1. HP 1000 이하 특수 패턴에 들어가면 왼쪽 화면 밖으로 이동한 뒤 왼쪽 벽으로 들어옵니다.
2. 몸 중심을 벽의 안쪽 경계에 맞춰 절반만 드러낸 채 약 0.8초간 대기합니다.
3. 아레나 안쪽 아래 **45도 고정 각도**로 레이저를 발사하며 반대 벽까지 이동합니다. 발사 중 각도는 바뀌지 않습니다.
4. 반대 벽을 통과할 때 레이저만 끄고, 멈추거나 가속을 다시 시작하지 않은 채 화면 밖까지 계속 이동합니다. 완전히 화면 밖으로 나간 뒤 감속·정지하고 0.1초 뒤 그쪽 벽으로 다시 들어옵니다.
5. 발사 벽과 안전 삼각형은 **왼쪽 → 오른쪽 → 왼쪽** 순서입니다.
6. 세 번째 발사 뒤에도 완전히 퇴장합니다. 화면 밖 측면에서 위로 상승 → 화면 위에서 중앙으로 이동 → 중앙에서 수직 하강합니다. 화면 안을 가로질러 복귀하지 않습니다.

HP 조건 1회, 편도 3회, 횡단당 최대 1회 피해, 패턴 중 무적, 가감속, 발사 중 카메라 쉐이크는 유지했습니다. 실제 타깃 유실·비활성화는 기존처럼 패턴을 중단합니다. 단순히 타깃이 멀어지는 것은 취소 조건이 아닙니다.

값을 계속 사용하려면 Play를 끈 상태에서 프리팹을 수정하세요. 빔 길이·두께·각도는 횡단 준비 시작 때 고정하며, 진행 중 값을 바꾸면 다음 횡단부터 반영합니다.

## 안전 구역과 판정

안전 구역은 발사 벽 아래의 **직각삼각형**입니다. 벽·바닥이 직각을 이루고, 처음 발사하는 빔의 벽 쪽 가장자리가 빗변입니다. 이후 빔은 같은 각도로 반대 벽 쪽으로 이동하므로 이 삼각형 안으로 돌아오지 않습니다.

빔의 중심선만 기준으로 잡으면 두께 때문에 경고 밖에서 맞을 수 있으므로, 경고 경계에도 빔의 반두께를 포함했습니다. 따라서 경고는 아레나 사각형에서 안전 삼각형을 뺀 오각형입니다. 몸 일부가 경계선 밖 위험 영역에 걸치면 맞을 수 있습니다.

경고 전체가 즉시 피해를 주는 것은 아닙니다. 실제 대각선 빔과 접촉해야 피해가 들어갑니다. 판정은 각도가 있는 OverlapBox이며, 빠르게 움직인 틱 사이도 검사합니다. 여러 콜라이더와 반복 접촉이 있어도 한 횡단당 최대 1회입니다.

### 고정 시각 길이와 피해 판정의 차이

시각 빔은 발사점부터 Beam Length만큼 그대로 그립니다. 바닥이나 벽에 닿아도 Transform의 길이를 줄이지 않습니다. 기존의 렌더 순서 때문에 앞쪽 지형에 가려지는 부분은 있을 수 있습니다.

피해 판정은 **설정 길이 이내이면서 기존 아레나 안인 부분**만 사용합니다. 바닥 밑이나 다른 방에 있는 타깃에게 예상치 못한 피해를 주지 않도록 기존 전투 범위 제한을 유지했습니다. Beam Length를 3처럼 짧게 설정하면 바닥에 닿지 않을 수 있으며, 이때 경고도 짧은 빔이 실제로 지나갈 높이까지만 표시됩니다. 긴 기본값에서는 기존 직각삼각형 안전 구역이 유지됩니다.

이번 알파 조정은 **레이저 전용 경고 프리팹**에만 적용했습니다. 원형 탄막 및 일반 몬스터의 경고 알파는 유지했습니다.

기존 대쉬 무적 확인 이슈는 이번 범위에 포함하지 않았습니다. 플레이어 피해 수신 코드와 무적 연동은 별도 확인이 필요합니다.

## 화면 밖 이동과 벽 가림

ArenaModule이 카메라 뷰포트의 월드 경계와 아레나 경계 중 더 바깥을 구하고, 보스 몸체 크기와 여유 거리까지 더합니다. 단순히 보스 중심만 화면 밖으로 나가는 방식이 아닙니다. 카메라가 없는 경우에는 아레나 경계를 사용합니다. 카메라가 전혀 다른 방을 보고 있다면 그 방까지 보스를 이동시키지 않고 아레나 기준으로 계산합니다.

RobotEyeBoss의 Body Visual 참조는 외곽 Shell SpriteRenderer입니다. 아트 크기가 바뀌면 외곽을 대표하는 Renderer를 연결하세요. 다른 씬의 카메라가 MainCamera가 아니면 Arena Camera를 직접 지정합니다. 경유점은 각 이동을 시작할 때 계산하므로, 보스 패턴 도중 카메라를 다른 방으로 급격히 이동시키는 연출은 별도 확인이 필요합니다.

절반 가림은 스프라이트를 잘라 교체하는 것이 아니라 **몸 중심을 벽 경계에 놓고 벽이 앞에서 그려지는 방식**입니다. 실제 맵의 벽 안쪽 X와 ArenaModule의 좌우 끝점이 일치해야 합니다. 벽의 높이도 보스를 가릴 만큼 충분해야 합니다.

## 렌더 순서

기존 Sorting Layer `Default` 안에서 Order in Layer를 다음과 같이 맞췄습니다. 새로운 프로젝트 공용 Sorting Layer는 추가하지 않았습니다.

- 맵 벽: 기존 0 유지.
- 보스 Shell / Eye / Pupil: -3 / -2 / -1.
- 실제 레이저 빔: -4.
- 보스 공격 경고 Canvas: -5. 레이저와 원형 탄막 경고 모두 적용.

즉 **맵 벽 > 보스 > 빔 > 경고**입니다. 일반 몬스터 경고 프리팹의 순서는 바꾸지 않았습니다. 다른 Sorting Layer나 SortingGroup을 사용하는 새 맵에서는 그 레이어/그룹이 우선하므로 위 관계를 다시 맞춰야 합니다. 다른 동료의 맵 에셋은 수정하지 않았습니다.

BossPatternTest에만 좌우 벽을 추가했습니다. 벽 안쪽은 X=-8 / +8로 기본 아레나와 맞췄으며, 충돌과 가림을 함께 확인할 수 있습니다. CTJ_MapTestScene은 이번에 수정하지 않았습니다.

## 직접 테스트

1. 작업 씬을 저장하고 `Assets/CTJ/Prototypes/Bosses/BossPatternTest.unity`를 열어 Play합니다.
2. `Deal 1500 damage (2500 -> 1000)` 버튼을 한 번 누릅니다. 보스가 왼쪽으로 사라졌다가 벽에서 절반만 나타나는지 확인합니다.
3. 벽에서 약 0.8초 멈추며 경고가 뜨는지 확인합니다. 왼쪽 벽 아래 삼각형만 비어 있어야 합니다.
4. 발사 중 빔의 기울기와 길이가 변하지 않는지 확인합니다. BeamVisual을 선택하면 바닥/벽 가까이에서도 길이에 해당하는 스케일이 일정해야 합니다. 현재 발사 최고 속도는 프리팹 20, 테스트 씬 오버라이드 50입니다.
5. 반대 벽에 가까워져도 느려지거나 붙어서 멈추지 않고 그대로 통과하는지 확인합니다. 벽을 통과할 때 빔·경고·쉐이크만 꺼져야 합니다. 화면 밖에서 정지한 뒤 반대 벽에 절반만 나타나는지 확인합니다. 세 번의 발사 벽은 왼쪽/오른쪽/왼쪽입니다.
6. A/D 또는 방향키로 삼각형 안에 몸 전체를 넣어 `Target hits`가 증가하지 않는지 확인합니다. 빔에 닿으면 30 피해, 한 횡단에서 최대 1회입니다.
7. 세 번째 발사 후 보스가 화면 안을 비스듬히 가로지르지 않고 위쪽 중앙에서 수직으로 내려오는지 확인합니다. 중앙 도착 후 무적이 풀리고 일반 패턴으로 돌아가야 합니다.
8. 다시 테스트하려면 Stop → Play합니다. 이 특수 패턴은 보스당 한 번만 발동합니다.
9. Play를 끈 뒤 MovingLaser의 Beam Length를 3으로 낮춰 재실행해 봅니다. 빔이 짧아지고, 바닥까지 닿지 않는 위치에는 경고/피해가 없어야 합니다. 확인 후 원하는 값으로 복원하세요. 기본 적용값은 18입니다.
10. BossLaserTelegraph의 Area Color 알파가 25인지, 이전보다 옅은 표시에서도 삼각형 안전 구역의 경계가 보이는지 확인합니다.

실제 맵에 적용할 때는 ArenaModule의 중심·벽·바닥 위치를 방과 맞춘 뒤 같은 항목을 확인하세요. 새 엘리트/보스 시스템이나 카메라 추적 시스템은 추가하지 않았습니다.

## 사용 문법과 이유

### enum과 FSM 상태 추가

`LaserEntering`, `LaserExiting`, `LaserHidden`, `ReturnRising`, `ReturnAbove`를 기존 상태 머신에 추가했습니다. 거대한 타이머 하나로 여러 행동을 섞지 않고 각 상태에 목적지 이동 또는 대기 한 가지를 맡겼습니다. 기존 enum 값에 영향이 없도록 뒤에 추가했습니다. 이동 계산은 기존 FlightModule, 공간 계산은 ArenaModule이 계속 담당합니다.

### 삼각함수와 고정 방향

`Mathf.Sin/Cos`로 각도를 단위 방향 벡터로 바꿉니다. 왼쪽 발사는 `(sin(angle), -cos(angle))`, 오른쪽은 X 부호만 반대로 만듭니다. 이 값은 ConfigureTraversal에서 한 번 결정합니다. 이전의 진행률에 따른 Pow/회전 계산은 제거했습니다.

### 내적과 다각형 자르기

`Vector2.Dot(점 - 발사점, 안쪽 법선)`으로 점이 경계선의 위험 쪽인지 판단합니다. 아레나 네 모서리를 순회하면서 위험 쪽의 점만 남기고, 선을 가로지르는 변에는 교점을 넣습니다. 이렇게 하면 빔 각도나 방 크기를 바꿔도 경고 모양이 계산됩니다. 별도 텍스처나 UI Toolkit이 필요 없습니다.

### Graphic, MaskableGraphic, override

기존 경고의 `Image` 필드를 그 부모 타입인 `Graphic`으로 넓혔습니다. 일반 적의 실제 Image 참조는 그대로 유지하면서, 보스에는 `ConvexPolygonGraphic : MaskableGraphic`을 사용할 수 있습니다. Unity가 이미 제공하는 상속 관계를 썼으며 새 추상 클래스/인터페이스는 만들지 않았습니다.

`OnPopulateMesh(VertexHelper)`를 override해 볼록 다각형을 삼각형 여러 개로 채웁니다. 경고 표시만 담당하고 피해는 스킬이 담당합니다. `SetVerticesDirty()`는 꼭짓점이 바뀌었을 때만 UI 메시 갱신을 요청합니다. 색과 점멸은 기존 AttackTelegraphUI를 그대로 사용합니다.

### IReadOnlyList와 is 패턴 매칭

`IReadOnlyList<Vector2>`는 받은 점 목록을 읽기만 하겠다는 뜻이며, 별도 프로젝트 인터페이스가 아니라 C# 기본 타입입니다. `areaImage is ConvexPolygonGraphic polygon`은 실제 타입을 확인하면서 안전하게 변수로 받는 문법입니다. 일반 Image 경고는 기존 사각형/원형 표시 경로를 유지합니다.

### 카메라 좌표 변환

`ViewportToWorldPoint`로 화면의 네 모서리를 월드 좌표로 바꿉니다. Bounds에 포함시킨 다음 보스의 반크기와 여유 거리를 더해 완전히 사라지는 목적지를 구합니다. 이동과 렌더 순서를 구분했으므로, 화면 밖 경유와 벽의 절반 가림을 각각 Inspector에서 확인할 수 있습니다.

### 감속 거리와 선택적 매개변수

일정하게 감속할 때의 이동 거리는 평균 속도 × 시간, 즉 `0.5 × 최고 속도 × 가감속 시간`입니다. `GetBrakingDistance()`로 이 거리를 구해 화면 밖 목적지에 더합니다. 속도나 가감속 시간을 늘려도 감속 구간이 벽 쪽으로 되돌아오지 않습니다.

`GetOutsidePoint(..., float brakingDistance = 0f)`의 `= 0f`는 선택적 매개변수 기본값입니다. 기존 준비 이동은 예전처럼 인자 두 개로 호출하고, 연속 퇴장만 감속 거리를 추가합니다. 벽에서는 `MoveTo()`를 다시 부르지 않으므로 기존 이동의 진행 시간과 속도가 그대로 이어집니다.

### 길이 스냅샷과 임시 목록

`_castLength`, `_castWidth`에 이번 횡단의 값을 기억해 시각 표시·판정·경고가 중간에 서로 다른 값을 쓰지 않도록 했습니다. 고정 길이 빔의 시작/끝 사각형을 합친 윤곽을 구하고 아레나와 겹치는 부분만 경고로 표시합니다.

다각형의 점을 순회하는 `foreach` 안에서 같은 목록을 직접 수정하면 오류가 발생할 수 있으므로 `_clipBuffer`에 결과를 모은 뒤 `Clear()`/`AddRange()`로 반영합니다. 새로운 시스템용 인터페이스나 추상 클래스는 추가하지 않았습니다.
