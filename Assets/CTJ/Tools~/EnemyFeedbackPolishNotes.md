# 사망 위치·혈흔 발생점·붉은 블링크·코인 회수 펀치

2026-11-05. 수정 범위는 `Assets/CTJ`입니다.

## 적용 내용과 원인

**Enemy01 사망 위치**

Zombie의 마지막 사망 스프라이트는 원본 시트의 7번 열에 속하지만, 그림이 왼쪽 셀 경계를 1픽셀 넘어 `rect.x = 223`부터 시작합니다. 기존 위치 보정은 이를 6번 열로 취급해서 마지막 프레임의 로컬 X가 0.64로 뛰었습니다. 적 루트 배율이 2.5라 최종 그림이 원점에서 1.6유닛 앞으로 옮겨진 상태였습니다.

`Enemy01_Zombie_Death.anim`의 실제 열 번호를 기준으로 X 보정을 다시 계산했습니다. 마지막 X는 0이며 Y의 접지 보정과 원본 PNG/슬라이스는 유지합니다. 마지막 피격의 넉백·블링크가 끝난 뒤 그 위치에서 사망 동작을 시작합니다. 정상적인 약 0.25유닛 피격 넉백은 여전히 발생합니다.

**혈흔 위치**

공용 공격 판정은 적 몸체 콜라이더의 ClosestPoint를 전달합니다. 콜라이더가 그림보다 넓으면 혈흔이 몸 앞의 빈 공간에서 나올 수 있었습니다.

EnemyParticleModule에 `Hit Sprites`와 `Hit Point Inset`을 추가했습니다. 전달된 피격점을 가장 가까운 몸체 SpriteRenderer의 월드 Bounds 안으로 제한한 뒤 해당 그림 중심으로 0.1유닛 넣습니다. 여섯 적 모두 실제 몸체 그림을 명시적으로 연결했습니다. 서로 떨어진 터렛 파츠는 합친 큰 사각형이 아니라 각 파츠 중 가장 가까운 범위를 사용합니다.

피격 스케일 변형이 발생점을 옮기지 않도록, EnemyBase는 체력 감소 확정 후 파티클 이벤트를 먼저 보내고 피격 변형을 시작합니다. 치명타에서는 피격 콜라이더를 꺼도 그림 범위로 보정할 수 있습니다. 기존의 잘못된 좌표 대체, 가해자로부터 멀어지는 분사 방향, 벽/바닥 흔적은 유지합니다.

이 보정은 스프라이트의 사각 Bounds 기준입니다. 매 타격마다 텍스처 알파를 읽어 픽셀 윤곽을 검사하는 방식은 사용하지 않습니다. 특정 적의 투명 여백이 크다면 Hit Sprites와 Inset을 해당 적에 맞춰 조절하세요.

**피격 색상**

여섯 적의 HitReactionModule을 밝은 적색 **#FF525C**, `Hit Color Blend = 0.65`로 조정했습니다. 원본 RGB 35%와 피격 RGB 65%가 섞이므로 원본의 무늬와 투명도는 보존됩니다. 점멸 시간과 피격 아웃라인 설정은 기존 값을 사용합니다.

**코인 회수 연출**

플레이어 중심에 도착해 소멸 애니메이션을 시작할 때, **원래 크기 → 1.35배 → 0.7배 → 원래 크기**를 0.24초 동안 재생합니다. 코인의 현재 크기를 기준으로 곱셈을 누적하지 않고 생성 시 저장한 크기에서 계산합니다. 소멸 중에도 플레이어 중심을 계속 따라갑니다. 기존 6프레임/12FPS 소멸 애니메이션의 지급 시점은 유지합니다.

현재 코인 프리팹의 바운스 비율은 사용자가 설정한 **0.5**입니다. 이번에는 회수 시 크기 연출만 추가했습니다.

## 직접 테스트 순서

1. 플레이어와 CurrencyManager가 있는 테스트 씬에서 Enemy01을 왼쪽과 오른쪽에서 각각 때립니다. 혈흔 시작점이 몸체 앞 빈 공간에 떨어져 있지 않은지 확인합니다.
2. 피격 시 붉은 기가 강한 밝은 색으로 점멸하고 원래 색/크기로 복구되는지 봅니다. 원하는 강도는 Hit Color Blend로 조절합니다.
3. Enemy01을 처치합니다. 마지막 넉백/블링크 후 쓰러지고, 바닥에 눕는 마지막 프레임에서 몸이 앞으로 순간 이동하지 않는지 봅니다. 적이 반대쪽을 향할 때도 확인합니다.
4. 코인이 바닥에서 튄 뒤 플레이어에게 도착할 때 커졌다 작아지는지 봅니다. 플레이어를 움직여도 몸체 중심을 따라가야 합니다.
5. 코인이 사라질 때 Gold가 한 번씩 증가하는지 확인합니다. Enable Collect Scale Pulse를 끄면 크기 연출만 꺼집니다.
6. 영구 조절은 Play를 종료한 후 해당 적/코인 프리팹에 적용합니다.

## 검증 결과

- Unity 런타임 코드와 검증 도구 컴파일 오류 없음. 여섯 적의 누락 스크립트/직렬화 참조 검사 통과.
- 좌우 방향의 좀비 사망: 마지막 로컬 X=0, 바닥 접지 유지. 프레임 사이의 최대 가로 변위는 약 0.150유닛으로 원본 동작의 작은 차이만 남음.
- 좌우 접촉점과 치명타: 펀치 스케일 적용 전 그림 범위에서 발생점 보정. 테스트 접촉점에서 약 0.134~0.136유닛 안쪽으로 조정됨.
- 피격 색/머티리얼 혼합값 적용 및 원래 색·크기 복구 통과.
- 코인 실측 최대 1.345배 / 최소 0.703배 후 원래 크기 복구. 이동/지연 대상의 중심 추적과 정확한 지급 통과.
- 기존 혈흔의 바닥·벽·일방향 발판·얇은 지형·지연 착지·사망 후 수명·연타 상한·씬 정리 검사 통과.
- 사망 프레임과 새 피격 색을 Unity에서 렌더링해 육안 확인. 원래 열린 씬은 저장하지 않고 복원.

VerifyEnemyFeedbackPolish.RunEdit / RunPlay, VerifyEnemyCoinReward.RunMagnetPlay, VerifyEnemyBloodSpray.RunPlay가 관련 검사입니다. VerifyEnemyFeedbackPolish.Apply는 기본값을 다시 적용하는 제작용이므로 단순 검증에는 실행하지 않습니다.

## 사용 문법과 이유

- **Bounds.ClosestPoint**: 콜라이더 접촉점이 그림 밖이면 가장 가까운 그림 범위의 좌표로 제한합니다. 입력이 안쪽이면 그대로 유지합니다.
- **Vector2.MoveTowards**: 보정한 점을 그림 중심으로 지정 거리만큼 이동합니다. 작은 적에서도 중심을 지나쳐 반대쪽으로 넘어가지 않습니다.
- **SerializeField + SpriteRenderer[]**: 다중 파츠 적의 몸체 그림을 명시적으로 연결합니다. 자동 검색에 UI나 임시 아웃라인이 섞이는 것을 피합니다.
- **Mathf.Lerp와 SmoothStep**: 두 크기 사이를 보간하되 각 구간의 시작과 끝을 완만하게 만들어, 확대/축소 방향이 갑자기 꺾이는 느낌을 줄입니다.
- **저장한 Vector3 × 배율**: 기존 프리팹 크기를 존중하고 매 프레임 크기가 누적되는 버그를 방지합니다.
- **AnimationUtility.Get/SetEditorCurve**: 런타임 보정 컴포넌트를 추가하지 않고 잘못된 애니메이션 에셋의 위치 키 자체를 수정합니다. 기존 스프라이트 참조 ID는 유지합니다.
- **이벤트 호출 순서**: 파티클이 피격 후 커진 그림을 읽지 않도록 시각 효과 시작 순서만 조정했습니다. 체력 감소 확정 후 이벤트를 발행하는 조건은 같습니다.
