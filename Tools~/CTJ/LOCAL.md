# CTJ 로컬 작업 규칙

갱신일: 2026-11-07

사용자가 프로젝트 폴더 정리 이후 직접 지정한 작업 범위다. CTJ 작업에서는 아래 범위가 기존 `Assets/CTJ` 및 `Assets/Branches/CTJ` 제한을 대체한다. 공용 문서나 과거 대화에 남아 있는 이전 폴더 안내를 근거로 수정 범위를 넓히지 않는다.

모든 경로는 프로젝트 루트 기준이며, 명시된 폴더와 그 하위에 적용한다. 수정 권한이 있어도 현재 요청과 무관한 변경은 하지 않는다.

## 스크립트 작업 허용 영역

- `Assets/_Scripts/UI/Enemy`
- `Assets/_Scripts/UI/HitFeedback`
- `Assets/_Scripts/Test/Enemy`
- `Assets/_Scripts/Agent/Enemies`

## 에셋 및 추가 작업 허용 영역

- `Assets/_Graphics/Animations/Enemy`
- `Assets/_Graphics/Assets/Enemy`
- `Assets/_Graphics/Effects`
- `Assets/_Graphics/Materials/Enemy`
- `Assets/_Graphics/Shaders/Enemy`
- `Assets/_Prefabs/Enemies`
- `Assets/_Scenes/Test`

게임용 C# 스크립트는 위의 스크립트 허용 영역에 둔다. 셰이더 등 해당 에셋에 필요한 파일은 해당 에셋 허용 영역에 둔다.

## 로컬 도구와 문서

- CTJ용 로컬 도구, 검증 보조 파일, 작업 문서는 `Tools~/CTJ` 안에 둔다.
- 사용자는 이 도구 영역의 생성을 명시적으로 허용했다. 기존 `Tools~`가 없으면 이 구조로 만든다.
- `Tools~`의 다른 위치나 다른 팀원의 도구 영역은 수정하지 않는다.
- 도구를 통해 변경하는 대상에도 위의 작업 범위 제한이 동일하게 적용된다.

## 범위 밖 작업과 재확인

- 허용 영역 밖의 파일과 코드는 읽고 참고할 수 있지만, 수정은 원칙적으로 거부한다.
- 범위 밖 수정이 필요하면 실행 전에 정확한 경로, 변경 내용, 필요한 이유를 설명하고 사용자에게 명확히 재확인을 받는다. 답을 받기 전에는 해당 변경을 하지 않는다.
- 액션 승인 설정이 '나 대신 승인'이어도 위 제한의 예외를 허가받은 것으로 해석하지 않는다. 원칙적으로 불허된 작업이 필요하면 사용자에게 **질문 형식으로** 묻고, 명시적인 답을 받은 뒤 진행한다. 자동 액션 승인은 이 답을 대신하지 않는다.
- 허용 영역 밖에 추가 디렉토리를 만들거나 그곳에서 작업하려는 경우에도 사전에 확인한다. 구조상 권장된다는 이유만으로 진행하지 않는다.
- 수정에는 생성, 내용 변경, 삭제, 이름 변경, 이동과 `.meta` 변경, 프리팹·씬 저장, 일괄 재직렬화 등도 포함된다. 이동은 출발지와 도착지 모두 확인한다.
- 기존 파일의 CTJ 관련 클래스명, 네임스페이스 또는 과거 소유자가 수정 권한을 의미하지 않는다. 현재 파일 경로로 판단한다.
- 공용 문서·설정·패키지 파일도 범위 밖이면 직접 고치지 않는다. 이번 규칙 저장은 공용 문서 수정의 허가가 아니다.

## 계속 적용하는 구현 규칙

- 기존 네임스페이스, asmdef, 폴더 규칙을 우선한다.
- 작업과 무관한 코드를 리팩터링하지 않는다.
- 요청 범위를 넘는 추가 작업은 먼저 승인받는다.
- 승인되지 않은 패키지를 설치하지 않는다.
- 인터페이스와 추상 클래스는 현재 필요한 경우에만 만든다. 아직 없는 미래 시스템을 위해 미리 만들지 않는다.
- 다른 작업자의 변경과 사용자의 미저장 씬 변경을 보존한다.
- 노션 기획서는 확인용으로만 사용하고 수정하지 않는다.
- 근접 공격의 위험 방향은 준비 자세로 전달한다. 붉은 판정 범위 UI는 근접 공격에 연결하지 않는다.

## 구현 후 확인과 설명

- 코드 구현 후 컴파일 오류와 참조 관계를 확인한다. 실행하지 못한 검증은 완료했다고 표현하지 않는다.
- 작업 설명에 사용자가 직접 따라 할 수 있는 테스트 환경, 과정, 기대 결과를 포함한다.
- 사용한 문법과 사용 이유를 별도로 설명한다. Unity 개발 약 1년 반의 경험을 기준으로 학습에 도움이 되도록 작성한다.
- 문서만 변경한 작업은 문서 내용과 저장 경로를 확인하며, 불필요한 게임 코드 수정이나 실행 검증을 추가하지 않는다.
