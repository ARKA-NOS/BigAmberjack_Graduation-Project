# Enemy20 천장 순찰체

기획 ID는 `enemy_ceiling_patrol`이다. Floating Shade의 대기·측면 비행·측면 공격·피격·사망 시트를 사용했다. 프레임마다 몸통 중심을 같은 기준에 놓고, 진행 방향을 읽을 수 있도록 앞쪽에 점멸하는 센서 스프라이트를 붙였다. [09-20 천장 순찰체 기획서](https://app.notion.com/p/09-20_-4189e7231ca781c8afd2f5817ab6d3f0)

| 항목 | 프리팹 설정 |
| --- | --- |
| 체력·방어 | 체력 55, 방어 1 |
| 이동 | 3.1유닛/초. 배치 높이에서 좌우 3유닛 순찰 |
| 추격 | 9유닛 안에서 감지해 플레이어 몸체의 높이에 접근. 12유닛을 넘으면 배치 지점의 X·Y로 복귀 |
| 피격 | 경직 0.2초, 기본 넉백의 90%, 기존 피격·사망 이펙트 |
| 수평 돌진 | 수평 거리 최대 2.4유닛, 높이 차 최대 0.6유닛에서 0.6초 동안 정지하고 센서 점멸 |
| 타격 | 발동 순간의 좌우 방향으로 최대 2.4유닛 이동. 높이를 유지하며 피해 11을 최대 한 번 적용 |
| 후딜·쿨타임 | 공격 애니메이션과 이동이 모두 끝나면 0.65초 정지. 쿨타임 2.6초는 타격부터 계산하고 빗나가면 발동부터 계산 |
| 처치 | 코인 5~8골드, 기존 사망 페이드와 처치 집계 |

돌진 속도는 테스트용으로 12유닛/초로 설정했다. `FlightDash`에서 속도·거리·후딜을, `FlightModule`에서 순찰 폭을 조정할 수 있다. 벽과 발판은 `Ground`·`Platform` 레이어로 검사한다. 비행은 장애물 표면을 따라갈 수 있지만 별도의 경로 탐색은 사용하지 않는다.

기획의 경험치 12는 지급 시스템을 찾지 못해 연결을 보류했다. 1스테이지 배수·발판 구간의 실제 배치는 남아 있다.

## 직접 테스트

1. `EnemyTestScene`에서 `Enemy20_CeilingPatrol`을 바닥보다 2~3유닛 높은 곳에 배치한다. 순찰할 공간을 확보하고 플레이어를 가까이 옮기면 같은 높이로 접근한다. 12유닛 넘게 멀어지면 원래 높이로 복귀한다.
2. 수평 2.4유닛 안에서 멈춰 센서가 점멸하는지 본다. 준비 중 순찰체의 반대쪽으로 넘어가면 발동 때 바뀐 방향으로 돌진한다. 돌진이 시작된 뒤에는 위나 옆으로 움직여 회피할 수 있다.
3. 돌진 경로에 벽을 둔다. 벽 직전에 멈추며, 공격 클립이 끝난 뒤 0.65초가 지나면 다시 비행한다. 처치 보상은 활성 `GameManager`가 있는 씬에서 확인한다.

Unity 격리 Play Mode에서 스폰 높이 순찰과 복귀, 센서 점멸, 발동 방향 고정, 수평 이동 2.4유닛, 단발 피해 11, 벽 앞 정지, 후딜과 쿨타임, 골드 수령을 확인했다. 공용 스킬 모듈을 사용하는 Enemy19의 지상 공격도 검증했다.

## 사용한 문법과 이유

- `GetModule<EnemyFlightModule>()`로 비행 모듈을 가져온다. 기존 FSM은 순찰·추격·공격을 관리하고, 비행 모듈이 붙은 적은 이동 요청을 비행 방식으로 처리한다.
- `Physics2D.BoxCast`로 물리 스텝에서 이동할 구간을 검사한다. 벽까지 남은 거리를 속도에 반영하고, 돌진 중 플레이어 콜라이더를 지나가더라도 피해를 한 번 적용할 수 있다.
- `Vector2.right`에 발동 순간의 좌우 부호를 곱해 방향을 저장한다. 돌진 속도의 Y 성분이 0이므로 비행 중 높이가 유지된다.
- `ObjectReferenceKeyframe`으로 준비 클립에서 센서 스프라이트와 빈 값을 번갈아 넣었다. 공격 클립의 `normalizedTime`이 1에 도달하면 이펙트가 없는 후딜 모션으로 전환한다.
