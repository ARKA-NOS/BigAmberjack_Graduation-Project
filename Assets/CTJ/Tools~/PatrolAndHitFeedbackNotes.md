# 스폰 기준 패트롤·흰색 피격·스케일 범위 (2026-10-25)

## 변경 사항

수정은 `Assets/CTJ`에만 적용했습니다. 동료의 코드와 맵 씬, 패키지는 수정하지 않았습니다.

### 1. 스폰 위치 기준 패트롤

- `EnemyPatrolModule.Initialize`에서 적의 월드 좌표를 저장합니다. 추격·넉백·배회 재시작·비활성화 후 재활성화가 있어도 기준점은 다시 잡지 않습니다.
- 룸 중심과 포탈 위치를 조회하던 코드를 제거했습니다. 기존 `Center Override` 항목도 제거했습니다.
- `Half Width`는 스폰 중심에서 좌우로 갈 수 있는 거리입니다. 예를 들어 스폰 X=10, Half Width=3이면 X=7~13에서 배회합니다.
- `Center Offset X`를 1로 지정하면 위 범위가 X=8~14로 이동합니다. `Patrol Speed`, `Pause Duration`은 기존과 같습니다.
- 선택 기즈모도 이 범위를 표시합니다. Edit 모드에서는 현재 배치 위치, Play 모드에서는 저장한 스폰 위치가 기준입니다.
- 현재 공용 스폰 포탈은 적을 비활성 홀더에 생성한 뒤 위치를 유지해서 꺼내므로, 실제 활성화 위치에서 초기화됩니다. 공용 스폰 코드는 읽기만 했습니다. 아직 존재하지 않는 풀링 재스폰 API는 추가하지 않았습니다.

### 2. 원본 무늬가 보이는 흰색 피격 점멸

각 프리팹의 `HitReactionModule > EnemyHitReactionModule > Blink`에서 설정합니다.

| 항목 | 현재 설정 / 의미 |
| --- | --- |
| Hit Color | 흰색. 다른 피격 색으로 변경 가능 |
| Hit Color Blend | 0.35. 0=원본 그대로, 1=색으로 완전히 덮기 |
| Blink Duration | 기존 0.35초 유지 |
| Blink Interval | 기존 0.05초 유지 |

스프라이트 자체를 투명하게 만드는 것이 아니라, **원본 그림의 RGB와 피격 색을 혼합**합니다. 따라서 눈·무늬가 남고, 원래 알파와 마스크는 유지됩니다. 강도를 낮추려면 Blend를 줄이세요. Blend=0에서는 아예 원본 머티리얼을 사용합니다.

Catto, MadGhost, 01, 02, RobotEyeBoss의 피격 색/혼합값을 연결했습니다. 보스의 넉백·스케일 비활성화와 터렛의 고정형 피격 설정은 유지했습니다. **01의 공격 준비 경고는 기존 붉은 단색 그대로**입니다.

### 3. 스케일 조절 범위 확대

`Scale Pulse Amount`의 Inspector 범위와 실제 코드 제한을 함께 **0~0.2 → 0~0.8**로 변경했습니다.

- 이미 사용자가 조정한 Amount=0.2, Duration=0.2초는 그대로 보존했습니다.
- 각 피격의 실제 변형은 Amount의 50~100% 중 무작위로 정해집니다. 가로가 늘면 세로가 줄고 반대 방향도 나옵니다.
- Amount=0.4라면 축별로 약 20~40% 변형합니다. 상한 0.8에서는 최대 20%~180%의 원본 크기 범위이므로, 값이 커질수록 연출이 강해집니다.
- 1 미만으로 제한하여 축이 0이 되거나 뒤집히지 않게 했습니다. Amount=0이면 변형하지 않습니다.
- 시각 전용 자식만 변형하므로 콜라이더·발사점·방향 전환 루트에는 영향을 주지 않습니다.

## 직접 테스트하는 순서

1. `Enemy01_TwistedArm`을 룸 중앙에서 떨어진 위치에 배치한 테스트 씬에서 Play합니다. 적의 PatrolModule을 선택하고 Scene 뷰의 Gizmos를 켭니다.
2. 배회 구간이 룸 중앙이 아닌 적의 시작 위치 주변인지 확인합니다. Half Width를 2로 바꾸면 스폰 X ±2로 좁아져야 합니다.
3. 플레이어로 유인해 추격시켰다가 멀리 벗어납니다. 다시 배회할 때 기즈모 중심이 추격 종료 지점으로 옮겨지지 않아야 합니다.
4. 플레이어 공격 또는 적 컴포넌트 메뉴의 `Test > Take 2 Damage (Play Mode)`로 피격시킵니다. 흰색 점멸 중 눈·무늬가 보여야 합니다.
5. Hit Color Blend를 0 / 0.35 / 1로 비교합니다. 각각 원본 / 무늬가 보이는 흰색 / 완전한 흰색이 되어야 합니다. Hit Color 변경도 확인합니다.
6. Scale Pulse Amount를 0 / 0.2 / 0.4 / 0.8로 비교합니다. 크기 변화가 강해지되, 연타 후에는 원래 크기로 돌아와야 합니다. 테스트 이후 원하는 값으로 되돌리세요.
7. 01의 공격 준비는 여전히 붉은 경고인지, 02의 전개·조준·공격 취소가 유지되는지 확인합니다. Play 중 설정 변경은 종료 시 되돌아가므로 최종 조절은 Edit 모드 프리팹에 적용합니다.

## 사용한 문법·API와 이유 — 학습용

- `Vector2` 값 저장: Transform 참조가 아닌 좌표 값을 복사해서, 적이 움직여도 저장된 스폰 위치가 함께 움직이지 않게 합니다.
- `Center => ...`: 계산 전용 프로퍼티입니다. 저장된 스폰 좌표와 Inspector의 오프셋을 합쳐 사용하며, 외부에서 기준점을 대입할 수 없습니다.
- `[Range(0f, 0.8f)]`와 `Mathf.Clamp`: 전자는 Inspector 슬라이더 범위, 후자는 실제 계산 범위입니다. 슬라이더만 바꾸면 기존 코드의 0.2 제한에 막히므로 둘 다 수정했습니다.
- 셰이더 `lerp(a, b, t)`: 원본 RGB와 피격 RGB를 t 비율로 혼합합니다. 알파는 별도 계산하므로 적 자체가 반투명해지는 방식과 다릅니다.
- `MaterialPropertyBlock`: 공유 머티리얼 에셋을 변경하거나 적마다 머티리얼을 복제하지 않고, 각 SpriteRenderer에 혼합값과 원본 색을 전달합니다. 같은 머티리얼을 사용하는 다른 적이나 공격 경고에 설정이 번지지 않습니다.
- `Shader.PropertyToID`: 셰이더 프로퍼티 이름을 한 번 ID로 변환해 반복 설정에 사용합니다.
- `GetPropertyBlock` / `SetPropertyBlock`: 피격 전의 렌더러별 값을 저장하고, 점멸 사이·종료·사망·비활성화 때 되돌립니다. 연타 중에는 피격 중 값을 원본으로 다시 저장하지 않습니다. 관련 블록은 초기화 때 생성하여 매 피격 할당하지 않습니다.
- 셰이더의 기본 혼합값은 1로 유지: 기존 공격 경고는 그대로 단색을 쓰고, 피격 모듈만 개체별 혼합값을 덮어쓰게 합니다.

## 검증

- Unity C# 및 피격 셰이더 컴파일, 적 프리팹 5종 참조 검사 통과.
- 스폰 중심 배회, 폭·오프셋 변경, 추격 후 복귀, 재활성화, 벽·낭떠러지 회피 검사 통과.
- 일반 적 4종에서 사용자 스케일 수치와 확장 상한 0.8 / 효과 없음 0을 검증. 연타, 원본 크기 복원, 방향 전환, 사망, 비활성화, 콜라이더·발사점 분리 검사 통과.
- 실제 URP 카메라에서 Catto / MadGhost / 터렛의 혼합 강도 0 / 0.35 / 1과 원본 알파 1 / 0.6을 검사. 중간 강도에서 무늬 유지, 알파 변화 없음, 종료 후 원본 픽셀 및 PropertyBlock 복원 통과.
- 전투 회귀 검사: 기존 붉은 공격 경고, 애니메이션 타격, 공격 취소, 터렛 전개·조준·발사체 생존 통과.
- 과거 테스트가 가정한 포탈 필드와 0.16초 복원 시간을 현재 코드·설정에 맞췄습니다. 렌더링 픽셀 비교는 먼 좌표의 GPU 정밀도 차이를 배제하도록 원점 근처에서 실행했습니다.
- 테스트는 저장하지 않은 독립 빈 씬에서 실행하고 원래 씬을 저장 없이 복원했습니다.
