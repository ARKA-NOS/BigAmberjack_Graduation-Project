# TestBossMap 바닥에 경고·레이저 맞추기

2026-11-02. 수정 범위는 Assets/CTJ입니다. SDW 맵·스폰 코드·데이터는 읽기만 했습니다.

## 원인과 수정

`SDW/Prefabs/Map/TestBossMap`의 Ground는 CompositeCollider2D이며, 맵 원점 기준 위쪽 바닥면은 Y=-2입니다. 보스 스폰 포인트는 (4,3)입니다. 기존 계산은 `보스 생성 Y - Floor Distance(5)`였으므로 기본 스폰에서는 맞지만, 보스를 테스트 씬처럼 Y=4에 따로 배치하면 기준 바닥이 Y=-1로 떠 있었습니다.

BossArenaModule에서 초기 아레나 중심 아래의 Ground를 Raycast로 확인해 실제 바닥을 기억합니다. 보스의 현재 이동 위치를 기준으로 하지 않으므로 횡단/복귀 중 높이가 흔들리지 않습니다. 레이저 단계 진입 때 다시 검사하여 맵이 늦게 준비된 경우도 반영합니다.

- 실제 바닥 → ArenaModule.FloorY → 레이저 경로와 경고 영역이 같은 기준을 사용합니다.
- 그림의 비율·기울기·배율은 유지하고 보스 발사 높이를 옮겨 접지합니다.
- 경고 UI의 하단도 바닥까지 표시합니다. 실제 피해 콜라이더는 그대로 두어 마지막 약 0.453유닛의 바닥 끝은 제외합니다.
- Scene 뷰에서 ArenaModule을 선택했을 때 보이는 주황색 바닥선도 탐지한 바닥에 맞춥니다.
- 자동 탐지가 꺼져 있거나 바닥을 못 찾으면 기존 Floor Distance 계산을 사용합니다.

## 인스펙터 설정

RobotEyeBoss / ArenaModule / BossArenaModule:

| 설정 | 기본값 | 용도 |
| --- | --- | --- |
| Detect Floor | 켬 | 실제 바닥 탐지 사용 |
| Floor Layers | Ground | 바닥으로 인정할 충돌체 레이어 |
| Floor Probe Distance | 30 | 초기 아레나 중심에서 아래로 검사할 최대 거리 |
| Floor Distance | 5 | 탐지 실패 또는 수동 모드의 기준 거리 |

한 높이의 바닥을 가진 현재 보스 방 기준입니다. 중간 발판 위에 초기 중심을 놓으면 그 아래에서 처음 만나는 Ground 윗면을 기준으로 사용합니다. 발판·경사면을 따라 레이저 길이를 매 프레임 늘리는 방식은 아닙니다.

## 직접 테스트

1. TestBossMap과 RobotEyeBoss가 배치된 씬에서 실행합니다. 맵 원본 프리팹을 수정할 필요는 없습니다.
2. 보스의 HP를 1000 이하로 내려 레이저 단계를 시작합니다. BossPatternTest의 Deal 1500 damage를 사용할 수 있습니다.
3. 좌→우, 우→좌, 좌→우 세 번 모두 경고 하단과 레이저의 바닥 접지선이 맵 바닥에 닿는지 확인합니다.
4. Scene 뷰에서 BeamVisual의 PolygonCollider2D를 선택합니다. 바닥 장식은 표시되지만 피해 판정은 그보다 약간 위에서 끝나야 합니다.
5. 보스 초기 Y를 1유닛 올린 경우에도 다시 실행해 같은 바닥을 쓰는지 확인합니다. 맵 전체를 위로 옮긴 경우에는 새 바닥 높이에 맞아야 합니다.
6. 기존 2.5캐릭터 안전 공간과 빠른 페이드가 유지되는지 확인합니다. 실제 게임 설정을 바꿀 목적이 아니면 테스트 위치 변경을 저장하지 않습니다.

## 검증

`VerifyBossMapFloor.RunPlay`는 SDW 맵의 임시 인스턴스와 기본 스폰보다 1유닛 높인 보스를 사용합니다. 3회 횡단에서 실제 CanvasRenderer 메시의 최하단과 레이저 접지선이 측정한 바닥에 일치하는지 검사합니다. 피해 콜라이더 하단의 기존 여유도 별도로 검사합니다.

`RunShiftedMap`은 맵 전체를 Y=11만큼 이동하고 보스 초기화 이후에 생성합니다. 탐지 실패 시 수동 기준을 사용하다가 레이저 단계 진입 때 새 바닥으로 다시 맞추는지 확인합니다. 트리거·다른 레이어 제외, 탐지 끄기, 너무 짧은 검사 거리의 수동 대체도 검증합니다.

실행 결과: 두 경우 모두 3회 횡단 통과. 원점 맵에서는 측정 바닥·경고 메시 하단·레이저 접지선이 약 -2, 이동한 맵에서는 약 9로 일치했습니다. 늦게 생성한 맵은 최초 수동 기준 10에서 실제 바닥 9로 보정됐습니다. 컴파일·프리팹 참조 검사 통과, 두 실행의 Error/Assert/Exception 0건입니다. SDW 맵과 사용자 BossPatternTest 씬 파일 해시는 작업 전후 동일했습니다.

## 사용 문법과 이유 — 학습용

- `Physics2D.Raycast`: 고정 거리 계산 대신 실제 충돌면의 좌표를 얻습니다. 아래 방향으로 검사합니다.
- `ContactFilter2D`: Ground 레이어만 검사하고 트리거를 제외합니다. 전역 Physics2D 설정을 바꾸지 않습니다.
- `RaycastHit2D[]`: 결과 배열을 재사용합니다. 접촉 법선의 Y가 0.5 이상인 윗면만 인정하고, 충돌체 내부에서 출발한 거리 0 결과는 제외합니다.
- `out float`: 탐지 성공 여부는 bool로, 바닥 높이는 out 매개변수로 함께 전달합니다.
- `Physics2D.SyncTransforms`: 방/보스가 배치된 직후의 Transform 변경을 물리 검사에 반영합니다. 초기화·패턴 진입에만 호출합니다.
- `Vector2` 값 복사: 경고용 꼭짓점의 하단만 접지선까지 옮깁니다. 원본 피해 콜라이더 점 배열은 수정하지 않으므로 바닥 끝의 피격 여유가 유지됩니다.
- `#if UNITY_EDITOR`: 탐지된 바닥 기즈모는 에디터에서만 표시합니다.
