# 임시 적 아웃라인 — 설정·검증·문법 설명

2026-10-26. 수정 범위는 Assets/CTJ입니다.

2026-10-28 추가: Enemy02에는 내부 파츠 경계를 숨기는 `Outer Silhouette Only`를 적용했습니다. 변경된 설정과 검증 결과는 [EnemyArtRefreshNotes.md](EnemyArtRefreshNotes.md)를 참고하세요. 아래 내용은 기본 안쪽 테두리 모드 설명입니다.

## 적용 결과

- Catto, MadGhost, 01, 02, 04, RobotEyeBoss 프리팹에 루트 자식 `OutlineModule`을 추가했습니다.
- 평소에는 짙은 붉은색, HP가 줄면 0.25초 동안 흰색 테두리입니다. 연타하면 마지막 피격부터 유지 시간을 다시 계산합니다. 회복은 흰색 표시를 연장하지 않습니다.
- 원본 그림의 **실루엣 안쪽 가장자리**에 기본 2픽셀 두께로 표시합니다. 외곽 메쉬를 키우거나 콜라이더를 변경하지 않습니다. 여러 파츠로 된 터렛·보스는 각 파츠의 가장자리를 표시합니다.
- 원본 SpriteRenderer 위에 전용 렌더러를 겹치므로, 기존 피격 점멸/공격 준비 경고/피격 크기 변형은 그대로입니다.
- 경직·넉백·점멸을 꺼도 HP 감소에 따른 아웃라인 색 전환은 동작합니다. 보스의 기존 경직·넉백 비활성화 설정도 유지했습니다.
- 조준선·투사체·UI는 대상에 포함하지 않았습니다. 기존 씬 파일은 저장하거나 수정하지 않았습니다.

## 조절 위치

적 프리팹의 `OutlineModule → EnemyOutlineModule`에서 설정합니다.

| 항목 | 기본값 | 의미 |
| --- | --- | --- |
| Normal Color | RGBA (0.55, 0.08, 0.08, 1) | 평상시 짙은 붉은색 |
| Hit Color | 흰색 | 피격 후 테두리 색 |
| Width | 2 | 화면 픽셀 기준 두께, 범위 0~6. 0이면 숨김 |
| Hit Duration | 0.25초 | 마지막 HP 감소 뒤 흰색 유지 시간. 0이면 색 전환 안 함 |
| Sprites | 해당 적 Visual의 렌더러 | 윤곽선을 표시할 원본들. 비워두면 초기화 때 소유 적의 SpriteRenderer를 수집 |
| Outline Material | EnemyOutline.mat | 공용 아웃라인 전용 머티리얼 |

`Width`는 원본 텍스처 픽셀 수가 아닌 **렌더링된 화면 픽셀 수**입니다. 카메라를 확대해도 테두리가 함께 과도하게 두꺼워지지 않습니다. 게임의 렌더 해상도나 렌더 스케일에 따라 최종 표시 두께는 달라질 수 있습니다.

현재 임시 스프라이트는 2픽셀이 기본입니다. 작은 적이 과하게 강조되면 1, 더 강하게 보이게 하려면 3 정도로 조절하세요. 프리팹이 아닌 Play 중 복제본에서 바꾼 값은 Play 종료 후 되돌아갑니다.

효과는 Play 중 생성됩니다. 편집 상태/프리팹 모드에서 미리 렌더러를 만들어 저장하지 않습니다. 다른 적에 사용할 때는 해당 EnemyBase의 루트 자식에 이 모듈을 하나만 추가하고, 전용 머티리얼과 Visual의 SpriteRenderer들을 연결하면 됩니다.

## 작동 방식과 분리

- `EnemyOutlineModule`은 기존 Module/IAfterInitModule 규칙을 사용합니다. HealthModule 초기화가 끝난 뒤 `OnHealthChanged`를 구독합니다.
- `delta < 0`일 때만 피격 타이머를 갱신합니다. 실제 피해가 무시되어 HP가 줄지 않으면 흰색으로 바뀌지 않습니다.
- 첫 LateUpdate에 원본 렌더러의 자식으로 `TemporaryOutline`을 생성합니다. 다른 모듈이 Awake에서 렌더러를 자동 수집할 때 이 임시 객체가 섞이는 것을 방지합니다.
- 매 LateUpdate에 sprite, flipX/Y, 레이어, 정렬 순서, SpriteMask 설정, 알파를 동기화합니다. 원본의 자식이므로 위치·회전·스케일 변형도 함께 따라갑니다.
- 테두리는 원본보다 Sorting Order가 1 높습니다. 기존 SortingGroup 내부에 남으므로 터렛/보스의 그룹 정렬을 따릅니다.
- 원본 렌더러의 color/sharedMaterial/MaterialPropertyBlock은 수정하지 않습니다. 모듈이 추가된 이후에도 기존 피격 셰이더의 원본 저장·복원 경로가 유지됩니다.
- 아웃라인 머티리얼은 하나를 공유하며, 각 렌더러의 두께/UV 범위는 MaterialPropertyBlock으로 전달합니다. 매 피격마다 머티리얼을 복제하지 않습니다.
- 사망 또는 소유 적/원본 렌더러 비활성화 시 테두리를 숨깁니다. 사망 애니메이션 자체는 기존대로 재생합니다.

현재 구현은 프로젝트에서 사용하는 일반 SpriteRenderer/프레임 애니메이션용입니다. 파츠가 여럿인 적을 하나의 합쳐진 외곽선으로 만드는 후처리 방식은 아닙니다. SpriteSkin 변형이나 특수 셰이더로 버텍스를 움직이는 새 적은 별도 확인이 필요합니다. 임시 구현이므로 원본 스프라이트마다 렌더러 하나와 가장자리 샘플링 비용이 추가됩니다.

## 끄거나 제거하기

1. 잠깐 끄려면 `EnemyOutlineModule` 체크를 해제하거나 `OutlineModule` 자식을 비활성화합니다. 생성된 테두리가 즉시 숨고 HP 이벤트 구독도 해제됩니다.
2. 완전히 제거하려면 적 프리팹의 `OutlineModule` 자식만 삭제합니다. 런타임에 삭제해도 생성한 TemporaryOutline 렌더러를 정리합니다.
3. 원본 SpriteRenderer의 머티리얼을 수동으로 되돌릴 필요가 없습니다. 게임플레이 모듈이 아웃라인을 참조하지 않으므로 공격/이동/피격/사망은 그대로입니다.
4. 셰이더와 머티리얼 파일까지 삭제하려면 먼저 모든 프리팹에서 모듈을 제거하세요. 다른 적이 같은 머티리얼을 공유할 수 있습니다.

## 직접 테스트하기

1. 저장한 CTJ_MapTestScene에서 기존 적을 보거나 적 프리팹을 배치하고 Play를 누릅니다. 연결된 프리팹 인스턴스에는 OutlineModule이 반영됩니다. 이미 Unpack한 별도 오브젝트는 직접 모듈을 추가해야 합니다.
2. 어두운 배경에서 평상시 붉은 테두리가 보이는지 확인합니다. 04번처럼 색이 어두운 적도 모양을 구분할 수 있어야 합니다.
3. 실제 플레이어 공격 또는 EnemyBase의 `Test/Take 2 Damage (Play Mode)` 메뉴를 사용합니다. 테두리가 0.25초 동안 흰색이고 이후 다시 붉은색이어야 합니다.
4. 짧게 연타합니다. 마지막 타격 뒤 0.25초까지 흰색이 유지돼야 합니다. 경직/점멸 설정을 꺼도 테두리는 바뀌는지 봅니다.
5. 01번의 공격 준비 색, 일반 적의 흰 점멸과 크기 변형, 좌우 반전/이동 애니메이션을 확인합니다. 테두리가 몸체와 어긋나면 안 됩니다.
6. 02번의 전개·회수를 확인합니다. 지면 아래의 파츠 테두리는 보이지 않아야 합니다.
7. Play 중 OutlineModule을 끄고 켜거나 삭제합니다. 테두리만 사라지고 기존 그림/피해 처리가 유지돼야 합니다.

미리보기: `EnemyOutline_Normal.png`, `EnemyOutline_Hit.png`. 실제 URP 카메라로 찍었으며 왼쪽부터 Catto, MadGhost, 02번 터렛입니다. 테두리 비교를 위해 해당 캡처에서만 기존 몸체 피격 점멸/크기 변형을 껐습니다.

## 사용 문법·API와 이유 — 학습용

- **이벤트 `+=` / `-=`**: HealthModule의 체력 변경을 구독합니다. 매 프레임 이전 HP와 비교하지 않아도 피격을 알 수 있고, 비활성화/삭제 때 구독을 해제해 사라진 모듈에 콜백이 남지 않게 합니다.
- **IAfterInitModule**: 기존 프로젝트의 초기화 후처리 인터페이스입니다. HealthModule의 최초 HP 설정이 끝난 뒤 이벤트를 연결합니다. 새 인터페이스는 만들지 않았습니다.
- **`LateUpdate`와 `[DefaultExecutionOrder(200)]`**: 애니메이션과 피격 모듈의 프레임 갱신 뒤 원본 스프라이트를 복사합니다. 피격 스케일이나 Sprite 프레임이 바뀐 뒤에도 테두리가 같은 상태를 보게 합니다.
- **`MaterialPropertyBlock`**: 공유 머티리얼은 유지하면서 렌더러별 셰이더 입력만 다르게 줍니다. `renderer.material`을 사용해 적마다 새 머티리얼이 생기는 것을 피합니다.
- **`Dictionary<Sprite, Vector4>` / `TryGetValue`**: Sprite의 UV 최소·최대 값을 캐시합니다. 애니메이션이 같은 프레임으로 돌아올 때 UV 배열을 매번 새로 읽고 계산하지 않도록 합니다. Vector4의 xy는 최소, zw는 최대 UV입니다.
- **`Time.time + hitDuration`**: 피격 시 종료 시각을 기록하고 현재 시각과 비교합니다. 연타할 때 코루틴이 여러 개 겹치지 않고 종료 시각만 갱신됩니다. 게임이 일시정지되어 scaled time이 멈추면 효과 시간도 멈춥니다.
- **`HideFlags.DontSave`**: 자동 생성한 보조 렌더러를 영구 씬/에셋 데이터로 저장하지 않게 합니다. 삭제 시 정리는 OnDestroy에서 별도로 수행합니다.
- **HLSL `ddx` / `ddy`**: 화면에서 옆 픽셀로 갈 때 UV가 얼마나 변하는지 GPU가 계산합니다. 여기에 Width를 곱해 화면 픽셀 기준 검사 간격을 구합니다. C#의 일반 미분 함수가 아니라 픽셀 셰이더의 이웃 픽셀 연산입니다.
- **주변 8방향의 알파 검사**: 현재 픽셀이 불투명하고 주변에 투명한 부분이 있으면 가장자리입니다. 중심 알파 × (1 - 주변 최소 알파)로 가장자리만 남겨 본문 그림을 덮지 않습니다.
- **UV 범위 제한**: Sprite Sheet에서 현재 프레임 밖을 투명으로 취급하고 텍셀 중심으로 샘플을 제한합니다. 옆 프레임의 그림이 테두리 계산에 섞이지 않도록 합니다.

## 검증 결과

- Unity C# 및 셰이더 컴파일, 6개 프리팹의 스프라이트/머티리얼/모듈 참조 검사 통과.
- 6종 Play: HP 감소, 연타 갱신, 회복 무시, 보스 면역과 독립 실행, 프레임/반전/정렬/마스크 동기화, 비활성화/재활성화, 삭제 후 렌더러 정리, 원본 머티리얼/PropertyBlock 유지 검사 통과.
- 실제 URP: 붉은 테두리 7,246픽셀이 모두 흰색 테두리로 변경. 원본 실루엣 밖으로 새로 표시된 픽셀 0, 내부 그림 픽셀 유지, 터렛의 지면 마스크 유지, 모듈을 끈 뒤 원본 픽셀 복원 확인.
- 기존 01 공격 경고 + 피격 점멸 + 스케일 변형 + 아웃라인 동시 실행 검사 통과.
- 기존 피격 렌더링의 혼합값 0/0.35/1 및 알파 1/0.6 회귀 검사 통과. 이 검사는 선택형 아웃라인을 끄고 원본 피격 효과만 비교하도록 수정했습니다.

생성 도구 `ConfigureEnemyOutline.Apply`는 이미 연결된 프리팹을 덮어쓰지 않습니다. 이후에는 인스펙터로 조절하세요. 읽기 전용 구성 검사는 `ConfigureEnemyOutline.Validate`, 런타임/렌더 검사는 `VerifyEnemyOutline`을 사용합니다. 모두 기존 Tools~ 규칙에 따라 게임 빌드에는 포함되지 않습니다.
