# 절벽 추격 방지 / 좀비 공격 / 아처 벽 앞 사격

2026-11-03. 변경 범위는 `Assets/CTJ`이며 공용 모듈·패키지·씬은 수정하지 않았습니다.

## 수정 내용과 원인

### 절벽에서 멈추기

기존 `EnemyMovementModule.MoveOnGroundTowards()`는 배회와 아처 거리 확보 때 벽·절벽을 검사했지만, 일반 추격의 `MoveTowards()`는 수평 속도를 바로 설정했습니다. 따라서 Ground 체크 레이어가 올바르더라도 플레이어를 따라 발판 끝을 지나갔습니다.

이제 공통 수평 이동 단계에서 몸체 앞쪽 바닥을 작은 `BoxCast`로 확인하고, 지지할 바닥이 없으면 X 속도를 0으로 만듭니다. 검사 거리는 `Obstacle Check Distance`와 다음 물리 프레임의 이동량 중 큰 값이므로 속도가 빨라도 미리 멈춥니다. 점프 중에는 마지막으로 밟은 높이까지 검사하여 아래층 바닥이 있다는 이유로 절벽 밖으로 이동하지 않습니다. 플레이어가 발판 안쪽으로 돌아오면 다시 추격합니다.

`CanMoveOnGround(direction, speed)`는 실제로 이동하지 않고 이동 가능 여부만 반환합니다. 배회·후퇴·후퇴 불가 시 공격 선택에서 같은 벽/절벽 판정을 사용합니다. 이번 변경은 AI의 자발적 이동에 적용되며, 피격 넉백이나 중력을 제거하지 않습니다.

Enemy01·02·04는 이미 Ground와 Platform 설정이 맞았습니다. 이전 테스트 모델인 Catto/MadGhost도 같은 발판에서 동작하도록 이동 검사와 TerrainBody의 Include/Exclude Layers를 Ground(6) + Platform(10)으로 맞췄습니다. 플레이어와 물리적으로 충돌하지 않는 구성은 유지합니다.

### 좀비(Enemy01)

| 항목 | 이전 | 현재 |
| --- | --- | --- |
| Enemy01 전용 Stats의 Attack Delay | 0.6초 | 0.35초 |
| MeleeAttack의 Post Blink Delay | 0.2초 | 0.1초 |
| 준비 자세부터 공격 클립 전환까지 | 0.8초 | 0.45초 |
| 공격 클립의 타격 이벤트 | 시작 후 0.05초 | 동일 |
| AttackHitbox Offset | (0.65, 0.34) | (0.425, 0.34) |
| AttackHitbox Size | (0.9, 0.65) | (1.35, 0.72) |

준비 클립이 마지막 준비 자세에 도달하는 0.35초는 확보하고, 이후 대기를 줄였습니다. 실제 타격까지는 약 0.5초이며 프레임에 따라 약간 차이가 납니다. 후딜·쿨타임·피해량 8은 유지했습니다. 공격 직전 색 점멸은 다시 켜지 않았습니다.

판정의 로컬 X 끝 1.1은 유지하면서 시작점을 0.2 → -0.25로 확장했습니다. 이제 몸통 영역(-0.25~0.25)이 판정 안에 들어갑니다. 좌우 반전에도 함께 뒤집히며, 몸체보다 훨씬 뒤쪽까지 때리지는 않습니다. 수치는 콜라이더의 로컬 좌표입니다. 현재 Enemy01 루트 스케일 2.5를 곱하면 실제 월드 범위가 됩니다.

### 아처(Enemy04)

`SkillModule → Skills → 해당 스킬 → Allow Close Attack When Retreat Blocked`를 추가하고 Enemy04에만 켰습니다.

- 평지에서 가까워지면 기존처럼 뒤돌아 뛰어서 최소 거리 5를 확보합니다.
- 뒤쪽 벽 또는 절벽 때문에 후퇴할 수 없으면 멈추고 플레이어를 바라보며 공격합니다.
- 이때 최소 사거리만 예외로 처리합니다. 최대 사거리, 착지, 시야, 높이, 쿨타임 등의 기존 조건은 유지합니다.
- 벽이 사라지거나 다시 후퇴할 수 있게 되면 다음 행동에서 정상 거리 확보로 돌아갑니다.
- 별도의 막힘 상태를 저장하지 않고 현재 지형을 검사하므로, 타깃 변경이나 벽 제거 후 예외가 남지 않습니다.
- 플레이어와 아처 사이를 벽/발판이 가리면 발사하지 않습니다. 기존 수평 사격과 다른 발판에서 거리 경계에 멈추는 동작을 유지합니다.

## 직접 테스트

1. 저장한 테스트 씬에서 Ground 또는 Platform 발판 위에 Enemy01을 놓고 플레이어를 발판 바깥이나 아래층으로 이동시킵니다. 좌우 모두 끝에서 멈추고, 안쪽으로 돌아오면 다시 따라와야 합니다.
2. Enemy01에 접근합니다. 준비 자세 후 약 0.5초에 피해가 발생하는지 확인합니다. 몸통에 겹쳐 서도 피해가 들어가야 하며, 한 번 휘두를 때 중복 피해는 없어야 합니다.
3. Scene 뷰에서 `Enemy01/Visual/AttackHitbox`의 BoxCollider2D를 선택합니다. 몸통부터 기존 전방 끝까지 연속된 범위인지 확인합니다. 반대 방향에서도 확인합니다.
4. Enemy04 뒤에 벽을 두고 플레이어가 5 이내로 접근합니다. 후퇴하다 벽 앞에서 멈춘 뒤 플레이어 쪽으로 돌아서 수평 사격해야 합니다. 반대쪽 벽에서도 반복합니다.
5. 뒤쪽 벽을 치우면 다시 거리를 벌리는지, 둘 사이에 벽을 두면 공격하지 않는지 확인합니다. 다른 발판 위·아래의 플레이어를 상대로 좌우 떨림이 없는지도 확인합니다.

준비 시간을 더 조정하려면 Enemy01 전용 Stats의 Attack Delay를 먼저 바꾸세요. `Fallback Attack Delay`는 해당 스탯을 읽지 못했을 때만 사용합니다. 추가 대기는 MeleeAttack의 `Post Blink Delay`입니다. 씬 인스턴스에서 같은 값을 별도로 Override했다면 해당 Override가 프리팹보다 우선합니다.

## 사용 문법과 선택 이유 — 학습용

- **`bool` 반환 함수**: `CanMoveOnGround()`는 가능/불가능만 알려주고 위치나 속도를 바꾸지 않습니다. 같은 판정을 배회와 공격 선택에서 재사용할 수 있습니다.
- **`out bool blocked`**: 이동 방향이라는 기존 반환값 외에 막혔는지도 함께 받습니다. 방향이 0인 경우는 도착·공중·장애물 등 여러 원인이 있으므로, 장애물 때문에 멈춘 경우만 구분하여 플레이어를 바라보게 했습니다.
- **`[SerializeField] private bool`**: 외부 코드에 쓰기 권한을 공개하지 않고도 인스펙터에서 스킬별 예외를 설정합니다. 기본값은 false이고 Enemy04에서만 켜므로 다른 적의 스킬 규칙을 바꾸지 않습니다.
- **`internal float MoveSpeed => moveSpeed`**: 같은 어셈블리의 거리 모듈이 실제 이동 속도를 읽을 수 있는 읽기 전용 프로퍼티입니다. 검사에서 다른 속도를 사용해 이동 가능 여부가 달라지는 것을 방지합니다.
- **`Mathf.Max`와 `Time.fixedDeltaTime`**: 한 물리 프레임에 갈 거리(`speed × fixedDeltaTime`)보다 앞을 확인하도록 합니다. 점프 중에는 현재 발 높이와 마지막 착지 높이의 차이만큼 아래로 더 검사합니다.
- **`(1 << 6) | (1 << 10)`**: Ground와 Platform 레이어 비트를 합친 마스크(1088)입니다. Collider의 Exclude에서는 이 두 레이어를 제외하지 않아야 실제로 밟을 수 있습니다.
- **단락 평가 `&&`, `||`**: 최소 사거리 안쪽일 때만 후퇴 불가 여부를 검사하고, 모듈이 없거나 비활성인 경우 예외를 적용하지 않습니다. 기존 일반 사거리 검사와 보스의 지정 스킬 진입점은 유지합니다.
