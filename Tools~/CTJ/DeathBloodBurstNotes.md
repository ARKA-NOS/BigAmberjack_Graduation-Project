# 적 사망 혈흔 폭발

작업일: 2026-11-11 / 사망 애니메이션 시작 시점 및 분사량 조정: 2026-11-11

## 결과와 조절 값

적이 마지막 타격을 받으면 HP가 0 이하가 된 프레임에 사망 애니메이션을 시작한다. 같은 프레임에 기존 방향성 피격 혈흔과 몸 중심의 사망용 혈흔이 나오며, 넉백·점멸·스케일 반응은 사망 애니메이션 위에서 계속 재생된다. 적 오브젝트가 사라져도 이미 나온 혈흔은 바닥·벽 접촉과 흔적 유지, 페이드 아웃을 끝까지 진행한다. Enemy01·Enemy02·Enemy04·Catto·MadGhost·RobotEyeBoss 프리팹에 연결했다.

`Assets/_Prefabs/Enemies/Effects/DeathBloodBurst.prefab`은 기존 `HitBloodSpray`를 복제한 전용 설정이다.

| 설정 | 일반 피격 | 사망 폭발 |
| --- | ---: | ---: |
| 입자 수 | 14~20 | 52~64 |
| 방출 속도 | 2.8~5.2 | 6~9 |
| 분사각 | 105도 | 360도 |
| 추가 상승 속도 | 1.2 | 0.5 |

중력 낙하, 바닥 흔적, 벽 흘러내림, 접촉 후 2~3초 유지와 페이드는 기존 `EnemyBloodParticle`을 공유한다. `EnemyParticleModule`의 `Death Burst Prefab`을 비우면 해당 적의 사망 분사만 끌 수 있고, `Death Burst Scale`은 개별 적 프리팹에서 조정할 수 있다. 분사량·속도·각도를 전체적으로 바꾸려면 사망용 프리팹의 `EnemyBloodParticle` 컴포넌트를 수정한다.

이번 단계에서는 요청대로 풀링을 추가하지 않았다. 기존 방식처럼 효과 오브젝트를 생성하고, 수명이 끝나면 제거한다. 공용 풀이나 다른 팀원의 폴더·씬은 수정하지 않았다.

## 동작 순서

1. `EnemyBase`는 HP가 0이 되면 `IsDead`를 정하고 마지막 `DamageReceived`를 발행한다. 기존 피격 혈흔과 넉백·점멸이 시작된다.
2. 같은 `Die()` 호출에서 사망 애니메이션의 첫 프레임을 즉시 반영하고 `DeathStarted` 이벤트를 한 번 발행한다. `EnemyParticleModule`이 이를 받아 `DeathBloodBurst`를 적 중심에 생성한다. 이미 사용 중인 `EnemyHitParticle`이 파티클과 수명을 관리한다.
3. `EnemyHitReactionModule.RemainingFeedbackTime`이 끝날 때까지 사망 애니메이션과 피격 반응이 함께 진행된다. 이후 콜라이더·물리를 정리한다. 제거 대기 시간은 사망 애니메이션을 시작한 시점부터 계산하고, 피격 반응이 더 길면 반응이 끝난 뒤 제거한다.
4. 효과는 적의 부모가 아닌 현재 씬의 루트에 생성되므로 적이 제거돼도 남은 연출을 재생한다. 같은 씬이 내려가면 함께 정리된다.

사망 애니메이션은 프리팹에 `Death Animator`와 `Base Layer.Death` 상태가 있는 적에서 재생된다. 현재 Enemy02와 RobotEyeBoss 프리팹에는 사망 애니메이터가 지정되지 않아, 그 둘은 즉시 사망 이벤트·피격 반응·혈흔은 실행되지만 전용 사망 애니메이션은 보이지 않는다.

일반 피격 효과와 사망 효과는 생성·수명 관리 코드를 공유한다. 사망 전용으로 새 인터페이스나 매니저를 만들지 않았다.

## 테스트 환경과 과정

환경: Unity 6000.3.22f1, 기존 Player와 Enemy01을 배치한 테스트 씬.

1. 적 프리팹의 `EnemyParticleModule`에서 `Death Burst Prefab`이 `DeathBloodBurst`를 가리키는지 확인한다.
2. Play 후 Enemy01을 처치한다. 마지막 타격 프레임에 사망 애니메이션이 시작되며, 기존 방향성 피격 혈흔과 더 많은 사망 혈흔이 동시에 보여야 한다. 넉백·점멸은 쓰러지는 동작 위에서 계속되어야 한다.
3. 적이 사라져도 피가 날아가고 바닥·벽에 남는지 확인한다. 닿은 흔적은 약 2~3초 후 서서히 사라진다.
4. 사망용 프리팹에서 `Speed Range`와 `Particle Count`, `Spread Angle`을 조절해 화면에 맞는 크기를 찾는다. Play 모드에서 바꾼 값은 종료 시 되돌아가므로 Edit 모드에서 저장한다.
5. 일반 피격만 주었을 때 사망용 혈흔이 나오지 않는지도 확인한다.

## 검증

- Unity 컴파일 오류 0, 경고 0. 적 프리팹 여섯 종의 사망 프리팹 참조를 확인했다.
- 저장된 Proto_MainHome을 보호한 별도 빈 Play 씬에서 실제 Enemy01을 처치했다. 마지막 타격 호출 직후 Death 상태와 점멸·넉백이 함께 시작됐고 `DeathStarted`는 한 번 발생했다. 반응은 약 0.36초 동안 사망 애니메이션 위에서 이어졌다.
- 이번 실행에서 사망 혈흔은 54개 입자를 냈고, 중심 기준 좌·우·상·하로 퍼졌으며 적 제거 후에도 남았다.
- 검증 후 원래 씬을 복원했으며 씬 파일은 수정하지 않았다. 재검증용 도구는 `Tools~/CTJ/VerifyDeathBloodBurst.cs`다.

## 사용한 문법과 이유

- `event Action DeathStarted`와 `?.Invoke()`: HP가 0이 된 프레임의 사망 시점만 알리고, 혈흔 모듈이 구독해 연출하도록 했다. 사망 로직이 구체적인 파티클 프리팹을 알 필요가 없다. `?.`는 구독자가 없으면 호출을 건너뛴다.
- `Animator.Play(DeathStateHash, 0, 0f)`와 `Animator.Update(0f)`: 사망 상태로 전환하고, 타격이 애니메이터 평가 이후 들어와도 같은 프레임에 첫 그림을 반영한다. 넉백·점멸 모듈은 계속 동작한다.
- 이벤트 `+=`와 `-=`: 모듈이 활성화될 때 구독하고 비활성화·파괴될 때 해제해 중복 호출과 남은 참조를 피한다.
- `[SerializeField] private ParticleSystem deathBurstPrefab`: 적별로 사망 효과를 연결하거나 끌 수 있으면서 다른 코드가 필드를 직접 수정하지 못하게 한다.
- `[Range(0f, 360f)]`: 기존 부채꼴 혈흔은 105도를 유지하면서 사망용 프리팹에 360도 분사각을 넣을 수 있게 했다. `EnemyBloodParticle.Emit()`의 구간별 각도 선택을 그대로 이용하므로 입자가 원 둘레에 고르게 분포한다.
- `SceneManager.MoveGameObjectToScene`: 파티클을 적의 자식으로 두지 않고 현재 씬에 소속시켜, 적 제거와 별개로 연출을 끝내며 씬 언로드 때 정리한다.
