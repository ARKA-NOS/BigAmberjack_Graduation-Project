# 아레나 범위 기즈모

## 사용법과 테스트

1. Scene 뷰에서 Gizmos를 켭니다.
2. 보스 아래 `ArenaModule` 오브젝트를 선택합니다. 컴포넌트가 접혀 있고 기즈모가 안 보이면 `Boss Arena Module`을 펼쳐 주세요.
3. 청록색 사각형은 왼쪽/오른쪽 벽과 바닥~레이저 발사 높이 사이의 전투 영역입니다. 위쪽 치수선에는 전체 가로 폭과 높이가 월드 단위로 표시됩니다.
4. 주황색 선은 바닥, 노란색 십자는 아레나 중심입니다. `Half Width = 8`이면 전체 가로 폭은 16입니다.
5. Play를 끈 상태에서 Half Width, Floor Distance, Laser Height를 바꾸면 즉시 범위가 달라지는지 확인합니다. 테스트용으로 바꾼 값은 원래 원하는 값으로 돌려놓으세요.
6. Center Anchor를 지정하면 해당 앵커 위치를 기준으로 미리 봅니다. 비워두면 부모 보스의 생성 위치를 기준으로 합니다. 모듈 자식의 위치나 보스 스케일은 전투 영역 크기를 변경하지 않습니다.
7. Play 중에는 보스가 이동해도 아레나 경계가 따라 움직이지 않아야 합니다. 실제 공격과 같은 초기 중심을 사용합니다. 런타임에 앵커를 움직여도 중심이 바뀌지 않는 기존 규칙을 그대로 반영합니다.

이 표시는 Scene 편집용입니다. 실제 공격 경고 UI나 콜라이더를 만들지 않으며, 카메라 바깥 퇴장 지점까지 포함한 영역도 아닙니다. 게임 빌드에는 포함되지 않습니다. 씬·프리팹 설정값과 보스 전투 동작은 변경하지 않았습니다.

## 사용 문법과 이유

- `OnDrawGizmosSelected()`: Unity가 오브젝트 선택 시 호출하는 기즈모 콜백입니다. 항상 표시해 씬을 복잡하게 하지 않고 설정하는 동안만 보여줍니다.
- `Gizmos.DrawWireCube()` / `DrawLine()`: 테두리·치수선·바닥선·중심 십자를 그립니다. Z 크기가 0인 XY 사각형이며, 숫자는 `Handles.Label()`로 표시합니다.
- `#if UNITY_EDITOR`: 에디터 전용 코드만 컴파일합니다. UnityEditor 참조와 기즈모 계산이 플레이어 빌드에 들어가지 않도록 했습니다. 별도 asmdef나 패키지는 추가하지 않았습니다.
- `Application.isPlaying`과 초기화된 `_owner` 확인: 편집 중에는 Initialize가 호출되지 않으므로 부모 보스/앵커 위치로 미리 보고, 실행 중에는 실제 전투에서 기억한 Center를 사용합니다. ExecuteAlways로 전투 초기화를 강제로 실행하지 않습니다.
- `Matrix4x4.identity`: 이미 월드 좌표로 계산한 사각형이 다른 기즈모의 변환 행렬에 영향을 받지 않게 합니다. 실제 아레나와 동일하게 보스 스케일/회전에 따라 크기를 바꾸지 않습니다.
- `try/finally`: 표시가 끝나면 기존 Gizmos 색과 행렬을 복원합니다. 다른 컴포넌트의 기즈모에 이번 설정이 남지 않게 합니다.
- `$"...{value:0.##}..."`: 문자열 보간과 숫자 포맷으로 폭·높이를 소수점 최대 두 자리까지 표시합니다.

## 검증

- Unity 컴파일 오류 0. UnityEditor 참조는 UNITY_EDITOR 조건 안에만 배치했으며, 새 직렬화 참조나 프리팹 연결은 없습니다.
- 편집 모드 9항목 통과: 생성 위치, 자식 모듈 오프셋 제외, 전체 폭/높이, 스케일/회전 비간섭, 설정 즉시 반영, 앵커, 단독 모듈, 최소 크기.
- 실행 모드 5항목 통과: 초기 앵커/생성 중심 고정, 이동하는 보스와 중심 분리, 실제 LaserBounds와 일치, 설정 변경 반영.
- 최종 Console Error/Exception/Assert 0. 임시 Preview Scene과 Play를 종료하고 원래 CTJ_MapTestScene을 복원했습니다. 사용자 씬/프리팹은 저장하거나 변경하지 않았습니다.

자동 검사는 좌표 계산을 검증합니다. Scene 뷰의 실제 색·숫자 가독성은 위 사용 순서로 직접 확인하세요.
