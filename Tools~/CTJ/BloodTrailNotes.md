# 혈흔 잔상 확인

## 적용

- 일반 피격 `HitBloodSpray`와 사망 `DeathBloodBurst`는 같은 `EnemyBloodParticle`을 사용한다.
- 공중에서 이동하는 각 혈흔 입자의 최근 위치를 기록하고, 한 이펙트당 하나의 메시로 얇은 잔상을 그린다. 바닥이나 벽에 닿으면 위치 기록을 멈추고 남은 잔상은 짧게 사라진다.
- `EnemyBloodParticle`의 **Air Trails**에서 `Trail Opacity`(기본 0.08), `Trail Duration`(0.14초), `Trail Width`(입자 크기 대비 0.2)를 조정할 수 있다. `Trail Opacity`를 0으로 두면 새 잔상 오브젝트가 만들어지지 않는다.
- 혈흔 입자는 코드가 직접 움직이고 파티클 자동 시뮬레이션은 꺼져 있다. 이 구조에서 Unity Particle System의 Trails 설정만 켜면 궤적이 생성되지 않아, 기존 혈흔 머티리얼을 사용하는 짧은 메시를 사용한다.

## 직접 확인할 환경과 순서

1. 일반 적과 플레이어가 있는 테스트 씬을 실행한다.
2. 적을 한 번 공격한다. 날아가는 혈흔 뒤에 매우 옅고 얇은 붉은 잔상이 잠깐 보이고, 입자가 바닥이나 벽에 붙으면 잔상이 사라지는지 확인한다.
3. 같은 적을 처치한다. 사망 시 더 많은 혈흔이 퍼질 때에도 각 입자 뒤에 같은 농도의 잔상이 보이는지 확인한다.
4. 두 이펙트의 `EnemyBloodParticle`에서 `Trail Opacity`를 0으로 조정해 잔상이 사라지고, 다시 0.08로 돌리면 돌아오는지 확인한다.

## 사용한 C# 문법과 이유

- `struct Drop`에 `TrailSlot`, `TrailHead`, `TrailCount`를 보관한다. 입자의 위치와 함께 잔상 기록을 추적해, 수명이 끝난 입자를 배열에서 교체해도 그 입자의 궤적을 유지한다.
- `% TrailSamples`는 고정 크기 배열을 순환하는 인덱스 계산이다. 최근 위치만 저장하므로 혈흔이 오래 살아도 기록이 계속 늘어나지 않는다.
- `List<Vector3>`, `List<Color>`, `List<int>`는 각각 메시의 꼭짓점, 색, 삼각형 인덱스를 담는다. 매 프레임 리스트를 `Clear()`한 뒤 재사용하여 반복적인 배열 할당을 줄인다.
- `sharedMaterial`로 기존 혈흔 머티리얼을 참조한다. 이펙트마다 머티리얼 사본을 만들지 않고, 꼭짓점 색상의 알파로 잔상 농도를 낮춘다.

## 자동 확인

`VerifyBloodTrails.RunPlay`는 격리된 빈 Play 씬에서 두 프리팹을 각각 발생시켜 메시 꼭짓점·삼각형 생성과 최대 알파 0.08 이하를 검사한다.
