# 적 슈퍼아머 설정·테스트·학습 메모

2026-10-27. 수정 범위: Assets/CTJ.

`EnemySuperArmorModule`은 공격 준비와 실제 공격 중 새 피격으로 발생하는 경직·넉백·공격 취소를 막는 선택형 모듈입니다. 요청대로 후딜에는 해제됩니다. 체력 감소, 사망, 흰색 점멸, 크기 변형, 피격 아웃라인은 기존대로 처리합니다.

현재 적 6종의 프리팹 및 씬에는 자동으로 추가하지 않았습니다. 필요한 엘리트/보스 프리팹에 선택해서 붙이면 됩니다.

## 적용 방법

1. Play를 종료하고 적 프리팹 또는 테스트할 씬 인스턴스를 선택합니다.
2. EnemyBase가 있는 루트 아래 빈 자식 `SuperArmorModule`을 만들고 `EnemySuperArmorModule` 컴포넌트를 추가합니다. 다른 모듈처럼 같은 EnemyBase 아래에 하나만 둡니다. 별도 참조를 드래그할 필요는 없습니다.
3. 기존 `EnemySkillModule`과 `EnemyHitReactionModule`은 그대로 사용합니다. 모듈 수집은 소유자의 Awake에서 이루어지므로 처음부터 추가한 상태로 Play/스폰해야 합니다. 이미 생성된 적에 런타임 AddComponent만 하는 방식은 지원하지 않습니다.
4. 평상시 피격 반응을 원한다면 HitReactionModule의 `Hit Stun Duration > 0`, `Enable Knockback`, `Cancel Attack On Hit`를 확인합니다. 넉백 설정은 기존 Speed 2, Duration 0.15를 사용하면 됩니다.
5. 모듈 체크 해제 또는 자식 비활성화로 보호를 끌 수 있습니다. 다시 켜면 현재 공격 단계를 기준으로 판단합니다. 완전히 제거하려면 편집 상태에서 해당 자식을 삭제합니다.

기존 RobotEyeBoss는 HitReactionModule의 경직·넉백·취소가 상시 꺼져 있습니다. 이 모듈을 추가하는 것만으로 기존 비활성 설정이 켜지지는 않습니다. 또한 현재 보스의 레이저 패턴에는 BossBase의 별도 무적 처리가 있으므로, 그 구간에 피해가 없는 것은 슈퍼아머 때문이 아닙니다. 이번에는 해당 보스 설정을 바꾸지 않았습니다.

## 보호 구간

| 상황 | 보호 여부 |
| --- | --- |
| Idle, 이동, 쿨타임 대기 | 해제 |
| 스킬의 공격 준비·마지막 경고 대기 | 유지 |
| 근접 애니메이션 시작부터 OnAttackHit 타격 판정 완료까지 | 유지 |
| 근접 타격 판정 완료부터 OnAttackFinished까지 | 해제: 빗나간 공격도 후딜로 처리 |
| 투사체 생성/발사 완료 후 Recovery Time | 해제 |
| 보스 원형 탄막 발사 완료 후 Recovery Time | 해제 |
| 보스 레이저 준비 및 지속 발사 | 유지 |
| 레이저 FinishTraversal 이후 | 해제 |
| IChargeSkill의 IsCharging 구간 | 유지 |
| 스킬 종료/중단, 소유자 비활성화, 사망 | 해제 |

공격 취소 방지는 **피격으로 인한 취소**에 적용합니다. 타깃이 사라지거나 스킬이 비활성화되는 등 기존 생명주기상의 종료까지 무시하지는 않습니다. 이미 발사된 투사체도 이번 변경으로 제거하지 않습니다.

슈퍼아머는 새 피격의 행동 방해만 막습니다. 이미 걸린 경직을 해제하는 정화 기능은 없습니다. 일반 실행 경로는 경직 중 새 스킬을 시작하지 못하므로 정상적인 공격에서는 기존 경직과 겹치지 않습니다.

## 처리 구조

1. 기존 EnemyBase.ApplyDamage가 HealthModule에 피해를 적용합니다. 치명타면 사망 처리가 우선입니다.
2. 살아 있다면 EnemyHitReactionModule이 EnemySuperArmorModule.IsProtected를 조회합니다.
3. 보호 중이면 경직 타이머 갱신, 넉백 시작, 피격에 의한 스킬 중단만 건너뜁니다.
4. 점멸과 크기 변형은 계속 실행됩니다. 아웃라인은 기존 HealthModule 이벤트를 통해 바뀝니다.

경직이 생기지 않았으므로 임시 흰색 경직 게이지도 차지 않습니다. 체력 바는 감소한 HP를 그대로 표시합니다.

후딜 판단을 위해 EnemyAttackSkill에 `IsRecovering`과 `BeginRecovery()`를 추가했습니다. 근접 타격 판정, 일반 투사체 발사, 원형 탄막 발사가 **완료된 다음** BeginRecovery를 호출합니다. 지속 레이저는 발사 중 호출하지 않으며 종료 시 보호가 풀립니다. 스킬 시작/종료/강제 중단에서 후딜 상태를 초기화합니다.

추가 스킬도 EnemyAttackSkill을 상속하면 준비·공격 구간은 그대로 사용할 수 있습니다. 해당 스킬의 실제 공격 판정이 모두 끝나 후딜에 들어가는 시점에 `BeginRecovery()`를 호출해야 합니다. 다단히트라면 마지막 타격 이후입니다. 이번 작업에서 새 인터페이스나 추상 클래스는 만들지 않았습니다.

공용 AbstractSkill을 직접 상속한 다른 스킬까지 후딜을 추측하지는 않습니다. 현재 그런 스킬에는 IChargeSkill의 차징 구간만 인식합니다. 이후 실제로 사용할 스킬을 추가할 때 그 스킬의 공격 단계에 맞춰 연결하면 됩니다.

## 직접 테스트하기

1. CTJ_MapTestScene에서 Enemy01_TwistedArm을 하나 복제하고 복제본에만 위 모듈을 붙인 뒤 Play합니다. HitReactionModule의 경직/넉백/취소는 켜 둡니다.
2. 플레이어가 공격 거리 밖에 있을 때 적을 때리거나 EnemyBase 컴포넌트 메뉴의 `Test/Take 2 Damage (Play Mode)`를 사용합니다. 체력이 줄면서 멈추고 밀려야 합니다.
3. 플레이어를 접근시켜 적이 공격 준비를 하는 동안 때립니다. 체력·피격 색·아웃라인은 변하지만 준비 동작과 공격은 이어져야 합니다.
4. 적이 타격한 직후 후딜에 때립니다. 다시 경직·넉백이 생기고 근접 동작이 취소되어야 합니다. 확인이 어려우면 일시정지/프레임 진행을 사용합니다.
5. MadGhost 복제본에도 모듈을 붙여 테스트합니다. 준비 중 피격에는 발사를 계속하고, 발사 후 Recovery Time에는 밀려야 합니다. 이미 날아간 탄은 유지되어야 합니다.
6. Play 중 모듈 체크를 끄고 다음 공격 준비 때 때립니다. 기존처럼 공격이 취소되어야 합니다. 다시 켜면 다음 준비부터 보호되어야 합니다.
7. HP를 충분히 낮추고 보호 중 치명타를 줍니다. 공격을 중단하고 정상적으로 죽어야 합니다.

직접 확인 후 테스트용 씬 인스턴스를 원하지 않으면 저장하지 않고 되돌리면 됩니다. 원본 프리팹에 Apply하는 것은 실제 적용할 적이 결정된 후 진행하세요.

## 검증 결과와 재실행

- Unity 컴파일 완료, 컴파일 오류 없음.
- 기존 Catto, MadGhost, 01, 02, 04, RobotEyeBoss의 스크립트/직렬화 참조 검사 통과. 기존 프리팹에 슈퍼아머가 자동 추가되지 않았음도 검사했습니다.
- 독립 Play 씬에서 실제 프리팹을 비활성 부모 아래 복제하고 모듈을 추가한 뒤 활성화했습니다. 원본 프리팹은 수정하지 않았습니다.
- 대기, 근접 준비/타격 전/후딜, 투사체 준비/발사 후, 원형 탄막, 지속 레이저, 체력 감소, 점멸·크기 변형·아웃라인, 모듈 비활성, 타깃 상실, 소유자 비활성/재활성, 치명타 검사 통과.
- 실제 애니메이션 타격 이벤트와 FixedUpdate 넉백 이동, 경직 종료, 쿨타임 대기, 다음 공격의 보호 재활성화도 통과했습니다.
- Console에는 테스트 피해 로그만 있었고 오류/예외는 없었습니다. 기존 씬을 저장하지 않고 복귀했으며 씬 파일 SHA256도 전후 동일했습니다.

검증 스크립트는 `Assets/CTJ/Tools~/VerifyEnemySuperArmor.cs`입니다. Tools~는 Unity 자동 임포트 대상이 아니므로 게임 빌드에 테스트 코드를 포함하지 않습니다. 기존 InvokeUnity.ps1의 run_script로 다음 순서대로 실행합니다.

1. VerifyEnemySuperArmor.RunEdit
2. VerifyEnemy01.BeginPlay (원본 씬은 저장된 깨끗한 상태여야 함)
3. Play 진입 후 VerifyEnemySuperArmor.RunPlay
4. VerifyEnemy01.StopPlay
5. Edit 복귀 후 VerifyEnemy01.RestoreScene

## 사용 문법과 이유 — 학습용

- **Module 상속과 Initialize**: 프로젝트의 모듈 수집 방식을 그대로 사용합니다. `owner.GetModule<EnemySkillModule>()`처럼 제네릭 함수로 필요한 타입의 모듈을 얻습니다. 별도의 매니저나 매 프레임 Find를 만들지 않았습니다.
- **읽기 전용 프로퍼티**: `IsProtected`는 조회 시 현재 스킬을 확인합니다. 보호 시작/종료용 별도 타이머를 복사하지 않아 애니메이션 종료나 강제 취소 후 보호 상태가 남는 것을 줄입니다. `IsRecovering => IsUsing && _isRecovering`의 `=>`는 getter 하나를 짧게 표현한 문법입니다.
- **프로퍼티 패턴**: `skill is EnemyAttackSkill { IsUsing: true, IsRecovering: false }`는 타입 확인과 프로퍼티 조건 확인을 동시에 합니다. 타입이 다르거나 null이면 false이므로 불필요한 캐스팅 없이 조건을 읽을 수 있습니다. 기존 피격 코드에도 쓰이는 문법입니다.
- **protected 메서드**: `BeginRecovery()`는 공격을 구현한 자식 클래스에서만 호출할 수 있습니다. 외부 모듈은 상태를 읽고, 후딜 시작 시점은 실제 타격을 처리한 스킬이 결정하도록 책임을 나눴습니다.
- **sealed / DisallowMultipleComponent**: 이 선택형 모듈을 상속 계층으로 확장할 필요가 없어 sealed로 두었습니다. 속성은 같은 GameObject에 중복 추가하는 것을 막습니다. 다른 자식에 같은 모듈을 또 추가하는 것까지 막지는 않으므로 EnemyBase당 하나만 둡니다.
- **Unity null 검사와 isActiveAndEnabled**: 파괴되었거나 꺼진 모듈/스킬/적은 보호를 제공하지 않게 합니다. 모듈이 아예 없는 기존 적도 기존 피격 로직으로 자연스럽게 처리됩니다.

## 이후 무적 모듈을 만들 때

이번 슈퍼아머는 피해를 차단하지 않습니다. 무적은 HealthModule의 체력을 깎기 **전**의 피해 수락 단계에서 판단해야 합니다. 피격 연출 모듈에서 막으면 이미 HP가 줄고 사망 이벤트도 실행된 뒤일 수 있습니다.

추후 실제 요구가 정해지면 피해를 받을지 판단하는 선택형 모듈을 별도로 붙이고 EnemyBase.ApplyDamage의 HP 변경 직전에 확인하는 방향이 적절합니다. 기존 BossBase.IsInvulnerable과의 관계도 그때 함께 정리해야 합니다. 지금은 미래용 무적 모듈/인터페이스를 미리 만들지 않았습니다.
