# laser_beam 원본 형태 유지

2026-11-02 최종 수정. Assets/CTJ 내부만 수정했습니다. 사용자 예시처럼 원본 기울기와 바닥 퍼짐을 유지하는 방식입니다.

## 현재 동작과 구성

- `laser_beam_0`의 가로·세로를 **동일하게 0.75배**로 표시합니다. 이전 0.3배보다 높이가 정확히 **2.5배**이며, 이미지 전체 크기는 약 **9.6675 × 9.0675유닛**입니다. 비율을 유지하므로 폭도 같이 커집니다. 원본 PNG, 슬라이스, PPU(100)는 그대로입니다.
- 45도 추가 회전과 가로/세로 개별 늘리기를 제거했습니다. 그림에 그려진 완만한 기울기를 그대로 사용하고, 반대 방향 횡단에서는 **좌우 반전만** 합니다. 바닥 퍼짐도 수평으로 유지됩니다.
- 그림을 바닥까지 늘리지 않고, 그림의 발사구와 접지 높이를 기준으로 **보스 경로 높이를 계산**합니다. 현재 보스 중심은 아레나 바닥 위 약 **8.9887유닛**입니다. Floor Distance가 5인 기본 프리팹의 Laser Height는 약 3.9887입니다.
- 원본 아래쪽의 희미한 투명 여백을 고려하여 이미지 높이의 3% 지점을 접지선으로 삼습니다. 그림을 잘라 새 파일을 만들지 않고, 바닥 렌더러가 겹친 가장자리만 가립니다.
- `BossSpriteBeam`은 원본 비율·배치·좌우 반전·중심부 콜라이더·짧은 페이드를 관리합니다. `BossLaserSkill`은 준비·피해량·횡단당 1회 피해·경고·흔들림 시작/종료를 담당합니다. `BossArenaModule`은 전달받은 높이로 경로를 계산합니다.
- 피해 판정은 **흰 중심부와 바로 주변을 따라가는 기울어진 사각형 1개**입니다. 원본 Physics Shape 전체를 복사하던 방식은 제거했습니다. 바닥 끝과 옆으로 퍼지는 광채는 장식이고 피해를 주지 않습니다. 하단 UV 0.08 기준 판정은 바닥 위 약 0.453유닛부터 시작하므로, 일반 플레이어는 중심부에 몸통이 닿으면 맞습니다.
- 이 콜라이더는 Trigger이고 일반 접촉과 콜백을 차단합니다. 명시적인 Overlap 조회로만 피해 대상을 찾습니다. 발사하지 않을 때에는 렌더러와 콜라이더를 모두 끕니다.
- 횡단을 시작한 벽에서 **플레이어 2.5캐릭터 폭**의 안전 공간을 비웁니다. 현재 공용 Player 프리팹의 몸통 Collider 폭 0.5유닛을 기준으로 **1.25유닛**입니다. 좌→우 횡단은 왼쪽, 우→좌 횡단은 오른쪽이 안전합니다.
- 준비 시간이 끝나면 보스가 먼저 벽에서 나와 이동합니다. **그림의 넓은 바닥 퍼짐까지 안전 공간을 완전히 벗어난 순간** 레이저 페이드 인과 화면 흔들림이 시작됩니다. **0.08초 페이드 인이 끝나 완전히 보인 뒤부터 피해를 검사**합니다. 보스 중심만 1.25유닛 이동하면 켜는 방식이 아니므로, 확대된 바닥 퍼짐도 안전 공간을 침범하지 않습니다.
- 경고는 중심부가 지나가는 영역을 계산하되 **하단을 실제 바닥 접지선까지** 표시하고, 아레나와 안전 공간 경계로 제한합니다. 넓은 옆 장식은 제외합니다. 경고의 바닥 부근은 여유 있게 표시하는 것이며, 실제 콜라이더는 바닥 위 약 0.453유닛부터 시작하는 기존 설정을 유지합니다. 방이 너무 좁아 안전 공간과 그림이 함께 들어갈 수 없으면 그 횡단은 발사 없이 끝냅니다.
- 횡단 종료 시 피해 판정은 즉시 끄고 **0.12초 페이드 아웃**으로 그림을 지웁니다. 정상 종료 후에도 그림은 보스를 따라 퇴장하며, 이때 추가 피해는 없습니다. 강제 취소·비활성화는 즉시 정리합니다.
- 흔들림은 **Amplitude=0.8, Frequency=32**로 강하게 시작하고 횡단이 끝날 때 **15% 강도**로 줄어듭니다. 이후 **0.18초** 동안 남은 흔들림이 0으로 부드럽게 사라집니다. 준비 중에는 흔들리지 않습니다.
- 횡단 속도는 현재 프리팹의 **30 → 27**로 10% 줄였습니다. 벽에서 멈추거나 감속하는 기존 동작을 추가하지 않습니다.

이전의 Beam Width, Beam Length, Diagonal Angle, Fit Length To Floor, Use Sprite Length 설정은 이 보스 레이저에서 제거했습니다. 폭이나 길이를 따로 늘려 원본 모양이 다시 변형되는 설정을 남기지 않았습니다. 사용자 씬의 이전 beamWidth 오버라이드는 새 코드에서 사용되지 않으며, 이번 작업에서 씬을 다시 저장하거나 수정하지 않았습니다.

## 조정 위치

`RobotEyeBoss → SkillModule → MovingLaser → BeamVisual`의 **BossSpriteBeam**에서 조절합니다.

| 설정 | 현재 값 | 의미 |
| --- | --- | --- |
| Uniform Scale | 0.75 | 가로·세로 공통 배율. 크기를 바꾸면 발사 높이도 실행 시 함께 계산합니다. |
| Muzzle UV | (0.37, 0.9) | 이미지 안에서 눈 아래에 연결할 발사구 위치. 원본 이미지의 왼쪽 아래가 (0,0)입니다. |
| Muzzle Offset | (0, -1.1) | FirePoint에서 그림의 발사구까지 월드 오프셋. 현재 눈의 아래쪽에 연결됩니다. |
| Impact UV | (0.6, 0.06) | 그림 속 빔 끝 중심. 발사 중 눈동자가 바라보는 방향에 사용합니다. |
| Floor Contact V | 0.03 | 원본의 희미한 아래 여백을 보정하는 접지선. 원본을 늘리거나 자르는 값이 아닙니다. |
| Hit Top UV | (0.43, 0.84) | 흰 중심부 판정의 상단 중심. |
| Hit Bottom UV | (0.61, 0.08) | 판정의 하단 중심. Y를 올리면 바닥에서 더 떨어집니다. 상단 Y보다 작아야 합니다. |
| Hit Half Width UV | 0.13 | 이미지 폭 대비 판정의 반폭. 줄이면 중심부 주변에 여유가 더 생깁니다. |
| Fade In Duration | 0.08초 | 완전히 보인 뒤 피해 시작. 0이면 즉시 표시·피해 가능. |
| Fade Out Duration | 0.12초 | 정상 종료 후 장식만 남는 시간. 0이면 즉시 숨김. |

`SkillModule → MovingLaser`의 **BossLaserShake → Amplitude**로 시작 흔들림 강도를, **End Strength(0.15)**로 횡단 마지막 비율을, **Fade Out Duration(0.18초)**으로 종료 여운을 조절합니다. 루트 **RobotEyeBoss → Laser Sweep Speed(27)**는 횡단 속도입니다. 진동 종료 시간과 레이저 그림의 종료 시간은 서로 다른 컴포넌트의 값입니다.

같은 `MovingLaser`의 **BossLaserSkill → Wall Safe Space**에서 안전 공간을 조절합니다.

| 설정 | 현재 값 | 의미 |
| --- | --- | --- |
| Character Width | 0.5 | 플레이어 한 캐릭터의 기준 월드 폭. 플레이어의 Collider나 배율을 바꾸면 이 값도 맞춰 줍니다. |
| Safe Character Count | 2.5 | 출발한 벽에서 확보할 캐릭터 수. 실제 안전 폭은 두 값의 곱입니다. |

플레이어 프리팹을 읽어 기준 폭만 확인했으며 공용 Player 코드는 수정하지 않았습니다. 크기가 서로 다른 플레이어에도 안전 폭이 임의로 변하지 않도록 자동 추적 대신 인스펙터의 기준값을 사용합니다.

바닥 기준은 이제 **ArenaModule → Detect Floor**를 켜서 실제 Ground 충돌면을 사용합니다. RobotEyeBoss 프리팹에는 켜 두었습니다. 초기 아레나 중심 아래로 검사하며 **Floor Layers=Ground, Floor Probe Distance=30**입니다. 트리거·다른 레이어·벽의 옆면·자신의 콜라이더는 제외합니다. 보스가 움직여도 검사 중심은 고정입니다. 초기화와 레이저 단계 진입 시 재검사하므로 맵 콜라이더가 늦게 준비된 경우도 반영합니다.

탐지를 끄거나 범위 안에 바닥이 없으면 기존 **Floor Distance=5**를 사용합니다. Laser Height는 탐지한 바닥과 원본 이미지 크기에 맞춰 계산합니다. SDW TestBossMap을 원점에 놓았을 때 실제 바닥 Y는 약 **-2**, 보스 스폰 Y는 **3**입니다. 보스를 Y=4에 따로 배치해도 바닥은 -2로 유지하고 발사 높이는 약 **6.9887**로 맞춥니다. SDW 프리팹은 수정하지 않았습니다.

바닥 탐지와 기즈모의 자세한 테스트·문법 설명은 `BossMapFloorNotes.md`에 있습니다.

## 직접 테스트

1. 저장된 `Prototypes/Bosses/BossPatternTest.unity`를 열고 Play합니다.
2. 왼쪽 테스트 패널의 **Deal 1500 damage**로 레이저 단계를 시작합니다.
3. 보스가 벽에서 먼저 나와 이동하는 동안 레이저가 꺼져 있는지 확인합니다. 왼쪽 출발 때는 왼쪽 벽 안쪽 1.25유닛, 오른쪽 출발 때는 오른쪽 벽 안쪽 1.25유닛에 플레이어 몸통 전체를 두면 피해를 받지 않아야 합니다. 경계에 걸쳐 몸통이 위험 영역으로 나가면 피격될 수 있습니다.
4. 안전 공간을 지난 다음 빔이 0.08초 동안 빠르게 나타나야 합니다. 완전히 보이기 전에는 맞지 않고, 보인 뒤 흰 중심부에 몸통이 닿으면 맞아야 합니다. 그림의 원본 비율과 바닥 접지는 그대로 유지됩니다.
5. 좌→우, 우→좌, 좌→우의 세 번 횡단을 확인합니다. 안전 공간이 출발한 벽 쪽으로 바뀌고, 반대편에서는 그림의 좌우만 반전돼야 합니다. 발사 중 눈동자도 그림 속 빔 방향을 봅니다.
6. Scene 뷰에서 BeamVisual의 PolygonCollider2D를 선택해 흰 몸통을 따라가는 좁은 판정을 확인합니다. 바닥 가장 끝과 옆의 장식 광채에만 닿으면 맞지 않아야 합니다. 한 횡단에서 여러 번 맞지는 않습니다.
7. 끝날 때 그림이 0.12초 동안 빠르게 사라지며, 사라지는 중에는 판정이 꺼져 있어야 합니다. 카메라는 초반에 강하게 흔들리다가 점점 약해지고, 종료 뒤 약 0.18초 안에 원위치로 돌아와야 합니다.
8. Uniform Scale 또는 Safe Character Count를 바꾸려면 Play를 종료한 뒤 변경하고 다시 실행합니다. 크기를 바꿔도 바닥 접지가 유지되고, 안전 공간을 바꾸면 경고와 실제 발사 시작 위치가 함께 바뀌어야 합니다.

비교용 캡처: `BossLaserShape_Close.png`. 캡처는 레이저 단계 종료 후 형태를 확인한 장면이라 눈동자는 기존 규칙에 따라 붉은 상태입니다.

검증: 컴파일·프리팹 참조 검사 통과. 3회 횡단 모두 페이드 인의 중간 알파, 완전 표시 후 판정 활성화, 페이드 아웃의 중간 알파와 판정 비활성화, 흔들림 강도 감소를 확인했습니다. 흰 중심부는 양방향 모두 겹침 있음, 바닥 끝은 양방향 모두 겹침 없음, 넓은 바닥 장식과 투명 모서리도 겹침 없음입니다. 위험 영역으로 이동한 첫 두 횡단은 각 1회, 마지막 안전 공간에서는 0회 피해였습니다. 원본 비율·접지·벽 안전 공간·강제 정리도 유지됐고, 카메라는 약 0.613유닛까지 흔들린 뒤 원위치로 돌아왔습니다. 실행 중 Error/Assert/Exception은 0건입니다.

기존 VerifyRobotEyeVisual 검증도 통과했습니다. 8방향 시선 추적, 5px 여백, 새 원본 빔 방향으로 시선 고정, 레이저 3회 후 중앙 복귀 중 붉은색 알파 전환을 확인했습니다.

최신 페이드 적용 후 안전 공간에 계속 머무르는 별도 실행에서도 세 번 모두 피해 **0 / 0 / 0회**, 실행 오류 0건이었습니다. 프리팹에 저장된 콜라이더도 런타임과 같은 네 꼭짓점으로 갱신하고 참조 검사를 통과했습니다. 위 눈동자 전용 검증은 이전 원본 형태 작업 시의 결과이며, 이번에는 레이저 판정·페이드·흔들림 검증을 실행했습니다.

## 사용한 문법과 이유 — 학습용

- **읽기 전용 계산 프로퍼티 (`=>`)**: `IsTraversalReady`는 준비가 끝나 이동 가능한 상태이고, `IsFiring`은 실제 빔까지 켜진 상태입니다. 둘을 구분해 레이저를 기다리느라 보스가 움직이지 못하는 순환 대기를 막습니다.
- **`[SerializeField, Min(...)]`**: 캐릭터 폭과 개수를 인스펙터에서 조정하면서 음수를 방지합니다. 실제 계산에도 `Mathf.Max`를 사용합니다.
- **`Bounds.min/max`와 삼항 연산자 (`조건 ? A : B`)**: 오른쪽 횡단에서는 그림의 가장 왼쪽, 왼쪽 횡단에서는 가장 오른쪽 경계를 검사합니다. 넓은 바닥 부분까지 안전 공간 밖으로 나가야 발사합니다.
- **발사 시작 시 이전 위치 초기화**: 이동 중에는 피해를 검사하지 않고, 첫 발사에서 `_previousOrigin`을 현재 위치로 바꿉니다. 비발사 상태로 지나온 안전 공간을 소급해 공격하는 일을 막습니다.
- **`Mathf.SmoothStep`와 경과 시간**: 프레임마다 고정 값을 더하는 대신 `(Time.time - 시작 시간) / 지속 시간`을 0~1로 계산합니다. 0.08초·0.12초 전환을 유지하면서 시작과 끝의 알파 변화를 부드럽게 만듭니다.
- **시각 상태와 피해 상태 분리**: `_emitting`, `_fadingOut`, `CanDamage`로 그림이 보이는 것과 공격 중인 것을 구분합니다. 페이드 인 완료 전과 페이드 아웃 중에는 판정을 끕니다. 스킬이 끝난 뒤의 짧은 페이드는 별도 컴포넌트의 Update가 마무리합니다.
- **`Mathf.InverseLerp`와 흔들림 강도 배율**: 실제 발사 시작 X부터 도착 X까지의 진행률을 구합니다. 방향이나 이동 속도가 달라도 횡단 끝에서 같은 비율로 약해지며, 종료 후에는 남은 강도부터 0까지 줄입니다.
- **균일 스케일과 Quaternion.identity**: 월드 X/Y 배율을 동일하게 적용하고 추가 회전을 없앱니다. 에셋 안에 그려진 기울기와 퍼짐이 그대로 보입니다. 부모 Transform의 배율은 보정합니다.
- **정규화 좌표와 Sprite.pivot / pixelsPerUnit**: 이미지 안의 발사구를 `(UV × 픽셀 크기 - 피벗) / PPU`로 Unity 로컬 좌표로 변환합니다. 그림의 연결 위치를 픽셀 파일 수정 없이 지정합니다. 이 UV 값은 UI Toolkit이나 셰이더 설정이 아닙니다.
- **`Vector2[4]`와 `PolygonCollider2D.SetPath`**: 상단·하단 중심과 반폭으로 네 꼭짓점을 만들고 기울어진 중심부 판정을 구성합니다. 장식용 광채까지 포함되던 원본 Physics Shape는 더 이상 사용하지 않습니다.
- **SpriteRenderer.flipX와 경로 X 부호 반전**: 렌더러 반전은 콜라이더를 자동으로 반전하지 않으므로 그림과 윤곽 좌표를 함께 뒤집습니다.
- **ContactFilter2D와 Collider2D.Overlap**: 일반 충돌 이벤트를 발생시키는 대신 실제 발사 중에만 타깃과의 겹침을 명시적으로 검사합니다. 지나간 중간 위치도 검사해 빠른 횡단의 판정 누락을 줄입니다.
- **List<Vector2>와 볼록 껍질**: 이동 전후 중심부 판정의 점들을 정렬하고 외곽을 연결하여 전체 경고 영역을 구합니다. 경고는 한 순간의 빔이 아니라 횡단 전체 영역입니다.
- **역할 분리**: 그림/윤곽 컴포넌트, 스킬 실행, 아레나 좌표를 나누되 새 인터페이스·추상 클래스·패키지는 추가하지 않았습니다.
