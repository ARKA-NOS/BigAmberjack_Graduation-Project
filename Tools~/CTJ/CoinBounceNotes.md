# 코인 바닥 튕김 무작위 범위

작업일: 2026-11-24

공통 코인 `Assets/_Prefabs/Enemies/Effects/EnemyRewardCoin.prefab`의 **EnemyRewardCoin > Ground Bounce**에서 조정한다. 처음 바닥에 닿을 때 코인마다 각도와 높이를 독립적으로 한 번씩 선택한다. 기존의 고정 Horizontal Retention 설정은 각도 범위로 대체했다.

| 항목 | 기본값 | 의미 |
| --- | --- | --- |
| Bounce Angle Range | -30 ~ 30도 | 수직 위가 0, 음수는 왼쪽, 양수는 오른쪽. 실행 시 -60~60도로 제한 |
| Bounce Height Multiplier Range | 1 ~ 1.35배 | 기존 기본 튕김 높이에 곱할 무작위 배율. 최소 높이 보장을 위해 1 이상으로 제한 |
| Bounce Height Ratio | 기존 0.5 | 플레이어 높이에서 기본 튕김 높이를 구하는 비율. 최소 절반 유지 |
| Minimum Bounce Height | 기존 0.8유닛 | 플레이어가 작아도 보장하는 기본 높이 |

각도와 높이 범위는 X에 최솟값, Y에 최댓값을 입력한다. 거꾸로 넣으면 작은 값과 큰 값으로 정리해서 사용한다. 양 끝을 같은 값으로 지정하면 해당 요소를 고정할 수 있다. 높이 배율은 속도 배율이 아니므로 1.35는 높이 35% 증가를 뜻한다.

각도를 바꿔도 수직 상승량은 기존의 최소 높이를 유지한다. 튕김 뒤 꼭대기에 도달하면 기존처럼 플레이어 중심을 추적한다. 첫 낙하, 초기 분산, 자석 가속, 트레일, 소멸 애니메이션, 수명 만료와 골드 정산 코드는 변경하지 않았다.

상자 코인은 이 공통 프리팹의 변형이므로 새 범위를 상속한다. 상자 영역의 코드나 프리팹은 수정하지 않았다. 상자 쪽에 기존에 저장된 초기 분산 설정도 유지한다.

## 직접 테스트

1. EnemyTestScene에서 적을 여러 마리 처치한다. 코인을 여러 개 보려면 현재처럼 보상 금액이 큰 적을 사용한다.
2. 코인들이 바닥에 닿았을 때 좌우 방향과 높이가 조금씩 달라지는지 확인한다. 발사 직후가 아니라 **첫 바닥 튕김**을 비교한다.
3. Bounce Angle Range를 -45~45로 넓혀 좌우 퍼짐을 비교하고, Bounce Height Multiplier Range를 1~1.6으로 바꿔 높이 차이를 비교한다.
4. 범위를 0~0도, 1~1배로 설정하면 수직 방향·기본 높이로 고정된다. 비교 후 원하는 범위로 되돌린다.
5. 꼭대기 이후 플레이어에게 날아오며 트레일이 보이고, 회수 후 골드가 정확히 들어오는지 확인한다.

## 검증 결과

검증 도구는 `Tools~/CTJ/VerifyCoinBounce.cs`다. `CheckAssets`로 적·상자 코인의 범위 및 스크립트·트레일·애니메이션 참조를 확인한다. EnemyTestScene의 Play Mode에서 `Run`을 실행하며 씬을 저장하거나 전환하지 않는다.

- 같은 입력 속도로 튕김을 128번 검사했다. 각도는 약 -29.59~29.93도, 왼쪽 57개·오른쪽 71개였다. 플레이어 높이 2유닛 기준 높이는 약 1.002~1.350유닛으로 분산됐다.
- 고정 범위, 역순 범위, 최소 높이·최대 각도 보정도 검사했다.
- 실제 낙하·바닥 접촉·튕김·자석 이동을 코인 16개로 실행했다. 측정한 상승 높이는 약 1.004~1.350유닛이었고, 튕김과 자석 이동의 트레일이 모두 확인됐다.
- 16개 × 3골드와 별도의 수명 만료 시험 7골드를 합쳐 55골드가 17번에 걸쳐 정확히 지급됐다. 생성 시 지급이나 중복 지급은 없었다.
- 컴파일 오류 0건. 기존 씬 파일을 저장하지 않았고, 작업 전부터 있던 다른 파일 변경을 유지했다.

## 사용한 문법과 이유

- `[SerializeField] Vector2`의 X/Y를 최소·최대 범위로 사용한다. Unity 인스펙터에서 값을 바꿀 수 있으며 별도의 데이터 클래스가 필요 없다.
- `Random.Range(float, float)`로 코인마다 각도와 높이를 따로 뽑는다. 초기 낙하 방향을 그대로 유지하는 대신 접촉 시 다시 선택해 규칙적인 튕김을 줄인다.
- `Mathf.Min/Max/Clamp`로 역순 입력과 허용 범위를 보정한다.
- 수직 속도는 기존처럼 `Sqrt(2 × 중력 × 높이)`로 구하고, 가로 속도는 `수직 속도 × Tan(각도)`로 구한다. 따라서 각도가 달라도 설정한 수직 높이를 유지한다. 삼각함수는 라디안을 받으므로 `Mathf.Deg2Rad`로 변환한다.
