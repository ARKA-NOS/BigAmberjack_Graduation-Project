# 피격 넉백·무작위 스케일 피드백 (2026-10-22)

## 적용 내용과 Inspector 설정

수정 범위는 `Assets/CTJ`입니다. 기존 피격 모듈을 확장했으며 패키지는 추가하지 않았습니다.

적 프리팹의 `HitReactionModule` 오브젝트에 있는 `EnemyHitReactionModule`에서 조정합니다.

| 항목 | 현재 값 | 의미 |
| --- | --- | --- |
| Knockback Speed | 6.4 | Catto / MadGhost / 01의 기존 5.1에서 약 25% 증가. 지속 시간을 유지해 밀리는 거리만 증가 |
| Knockback Duration | 기존 값 유지 | Catto / MadGhost 0.18초, 01은 0.2초 |
| Enable Scale Pulse | 일반 적 4종 켬 | 피격 시 시각 전용 스케일 변형. 이 옵션만 꺼도 기존 점멸·넉백은 유지 |
| Scale Pulse Amount | 0.08 | 매 피격에 최대치의 50~100%, 즉 4~8%를 무작위로 선택 |
| Scale Pulse Duration | 0.16초 | 맞는 순간 변형하고 부드럽게 원래 크기로 돌아오는 시간. 경직 시간과 무관 |
| Scale Targets | 그래픽 전용 자식 | Catto / MadGhost / 01은 HitVisual, 02는 Body 및 Launcher |

한 번 맞을 때 가로를 늘리면 세로는 줄이고, 반대 방향도 무작위로 선택합니다. 같은 피격의 여러 대상에는 같은 비율을 적용합니다. 기존 붉은색 점멸 및 공격 취소는 유지합니다. 기존과 같이 치명타격은 사망 처리가 우선하며 남아 있는 피격 효과는 복원합니다.

02 터렛은 **넉백 끔 + 제자리 피격 경직**을 유지합니다. 보스 프리팹은 수정하지 않았고 새 스케일 기능도 기본 꺼짐입니다. 보스에 나중에 적용할 때는 옵션을 켜고 시각 전용 대상을 직접 지정하면 됩니다.

## 시각 계층을 분리한 이유

Catto / MadGhost / 01은 다음 구조로 연결했습니다.

```text
Enemy
└─ Visual                 방향 전환 담당
   ├─ HitVisual           기존 SpriteRenderer / Animator / 관련 컴포넌트. 피격 스케일만 담당
   └─ AttackHitbox 또는 FirePoint   기존 판정 크기와 발사 위치 유지
```

기존 렌더러와 Animator를 새로 만들지 않고 그대로 옮겨 스킬·사망 애니메이션·이벤트 참조를 유지했습니다. 클립이 하위 경로나 Transform 스케일을 애니메이션하지 않는지도 확인했습니다.

터렛은 기존 계층을 유지합니다. Body와 Launcher 그림만 변형하고 RiseRoot, LauncherPivot, FirePoint, 지면 마스크 및 콜라이더는 제외합니다.

`Scale Targets`에 적 루트, 방향 전환용 부모, 발사 위치가 포함된 부모를 넣지 마세요. 코드는 소유 적 밖의 대상 및 물리 컴포넌트가 포함된 대상도 제외하지만, 발사 위치와 방향 전환 부모까지 자동 추측하지는 않습니다. 스케일을 키프레임으로 제어하는 애니메이션이 추가되면 별도의 그래픽 전용 부모를 사용해야 합니다.

## 직접 테스트하는 방법

1. `CTJ_MapTestScene`에서 해당 프리팹 인스턴스로 Play합니다. 플레이어의 공격으로 적을 맞히거나, 적 루트의 EnemyBase 파생 컴포넌트 메뉴에서 **Test → Take 2 Damage (Play Mode)**를 실행합니다.
2. Catto / MadGhost / 01이 전보다 조금 더 멀리 밀리고, 그림이 약하게 가로 또는 세로로 눌렸다가 돌아오는지 확인합니다. 기존 붉은 점멸도 함께 나와야 합니다.
3. 빠르게 여러 번 맞혀도 크기가 계속 커지거나 작아지지 않아야 합니다. 피격 중 방향을 바꿔도 바라보는 방향이 복원 때문에 뒤집히면 안 됩니다.
4. Scene 뷰에서 콜라이더와 AttackHitbox 또는 FirePoint를 확인합니다. 피격 시 그림만 변형되며 판정 크기나 발사 위치가 스케일 때문에 바뀌지 않아야 합니다. 실제 넉백에 의한 전체 이동은 정상입니다.
5. 02 터렛은 움직이지 않고 몸통·런처 그림에만 효과가 적용되어야 합니다. 전개·조준·발사 후 고정·수납 동작이 그대로인지 확인합니다.
6. HitReactionModule의 **Enable Scale Pulse**를 끄면 스케일 변화만 없어지는지 확인합니다. 강도는 Amount, 복원 시간은 Duration으로 조정합니다. Play 중 변경은 종료하면 되돌아가므로 최종 값은 Edit 모드에서 프리팹에 적용하세요.
7. 연속 피격 중 적을 비활성화하거나 처치했을 때 변형이 남지 않는지 확인합니다.

## 이번에 사용한 문법·Unity API와 이유

- `[SerializeField] private`: 외부 코드가 임의로 바꾸는 공개 필드 대신 Inspector에서 설정하도록 했습니다. `[Range]`, `[Min]`, `[Tooltip]`은 설정 범위와 용도를 안내합니다. 런타임 값도 `Mathf.Clamp`로 제한합니다.
- `Transform[]` 배열: 여러 그래픽 조각을 하나의 모듈로 다룹니다. 터렛처럼 몸통과 런처가 분리돼도 새 클래스를 만들 필요가 없습니다. 초기화 시 배열을 복사해 피격마다 배열을 할당하지 않습니다.
- `Random.Range(0.5f, 1f)` / `Random.value`: 최대 변형의 절반~전체 강도와 변형 방향을 피격마다 고릅니다. 매 프레임 난수를 다시 고르지 않으므로 덜덜 떨리는 연출이 되지 않습니다.
- `Vector3.Scale`: 원래 스케일에 축별 배율을 곱합니다. `Vector3.one`으로 복원하지 않고 저장한 스케일을 사용하므로 원래 크기와 Z값을 보존합니다.
- `Mathf.SmoothStep`: 0~1의 진행률을 부드러운 곡선으로 바꿔 원래 크기로 돌아올 때 갑자기 멈추지 않게 합니다.
- `LateUpdate`: 점멸과 별도로 매 프레임 복원 상태를 갱신합니다. 점멸이 꺼져 있어도 스케일 효과는 동작합니다. 방향 전환과는 다른 Transform을 써서 서로 덮어쓰지 않습니다.
- 원본 저장/복원 + `OnDisable`: 새 피격 전 먼저 이전 효과를 복원해 누적 변형을 막습니다. 사망·비활성화·옵션 해제에도 원본으로 복원합니다. 효과를 위해 코루틴이나 임시 오브젝트를 매번 생성하지 않습니다.

## 데미지 인디케이터 조사 — 수정 없음

현재 `Assets`의 코드·프리팹·UI 자료에서 **피격 위치에 피해 숫자를 띄우는 전용 인디케이터**는 찾지 못했습니다. 기존 기능은 다음과 같습니다.

- `Assets/Lrw/Script/UI/PlayerUI/HUD_UI/HP_UI/PlayerHealthUIBinder.cs`: 플레이어 HP 바, 지연 HP 바, `현재 HP / 최대 HP` 텍스트. 개별 피해 숫자 팝업은 아닙니다.
- `Assets/Lrw/Script/Agent/HealthSystem/HealthModule.cs`: 현재 체력·체력 변화량·최대 체력을 전달하는 `OnHealthChanged` 이벤트.
- 신규 체력 계층에도 체력 변경 이벤트와 HUD 바인딩이 있습니다. 공용 VFX 모듈은 효과 재생용이며 피해 숫자 표시 자체는 확인되지 않았습니다.

나중에 표시 기능을 붙일 때 기존 체력 변화 이벤트를 활용할 여지는 있습니다. 회복과 피해, 원래 공격력과 실제 감소량을 구분하는 정책은 그때 정하면 됩니다. 이번에는 인디케이터 생성·연결 및 동료 영역의 코드를 수정하지 않았습니다.

## 검증 기록

- Unity 스크립트 컴파일: 오류 없음.
- 프리팹 4종 및 보스 옵션 검사: Missing Script / 끊어진 참조 없음. 기존 타 컴포넌트 직렬화 값 보존 확인.
- 독립 빈 씬에서 `VerifyEnemyHitScale.RunPlay`: 4종 무작위 변형, 24회 연타, 1이 아닌 원본 스케일, 중간 보간, 방향 전환, 물리 판정·발사점 분리, 옵션 해제, 비활성화, 사망 복원 통과.
- 동일 조건의 넉백 비교: Catto / MadGhost 약 0.486 → 0.610 Unity 단위, 01 약 0.537 → 0.674 단위. 약 25.5% 증가. 실제 값은 FixedUpdate 시점·지형에 따라 조금 달라집니다.
- `VerifyEnemy01.RunPlay`: 배회/벽/낭떠러지/추격/애니메이션 타격/HP/피격 취소/사망 회귀 검사 통과. 최초 검사는 테스트가 배회 폭 3을 가정하지만 현재 프리팹은 6으로 조정돼 있어 실패했습니다. 테스트 복제본에만 고정 수치를 지정한 뒤 통과했으며 프리팹의 배회 수치는 변경하지 않았습니다.
- `VerifyEnemy02.RunPlay`: 전개/조준선/조준 고정/피격 경직·취소/공격 피해/수납/사망 후 발사체 유지/지형 충돌 통과.
- 테스트 종료 후 원래 CTJ_MapTestScene을 저장 없이 다시 열었습니다. 씬과 보스 프리팹 파일의 해시가 작업 전과 동일함을 확인했습니다.

재검증 도구는 `Tools~` 아래에 있어 게임 빌드에 포함되지 않습니다. `ConfigureEnemyHitScale.Apply`는 4종 피격 설정을 이 문서의 값으로 맞추므로, 추후 수치를 직접 조정한 뒤에는 검사 전용 `Validate`를 사용하세요.
