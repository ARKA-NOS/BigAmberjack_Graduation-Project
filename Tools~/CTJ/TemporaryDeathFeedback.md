# 임시 사망 폭발 연출

적용일은 2026-11-23이다. Enemy17~22와 Boss23의 사망을 즉시 터지는 느낌으로 비교하기 위한 임시 설정이다.

공통 설정은 [TemporaryDeathFeedback.asset](C:/Users/USER/BigAmberjack_Graduation-Project/Assets/_Prefabs/Enemies/Effects/TemporaryDeathFeedback.asset)에 모았다. 각 적 루트의 EnemyBase **Death Feedback Settings**에 같은 SO를 연결했다. 기존 적·파티클·쉐이크의 원래 수치는 유지하고 재생할 때 추가 배율을 전달한다.

## 즉시 복구하는 방법

1. 위 SO를 선택하고 **Use Temporary Feedback**을 끈다.
2. 이후 타격·사망부터 아래의 빠른 페이드, 분사 속도·개수 추가 배율, 쉐이크 추가 배율이 모두 해제된다.
3. **Use Temporary Feedback**을 다시 켜면 임시 설정으로 돌아온다.

한 적만 기존 방식으로 사용할 때는 해당 적 루트의 **Death Feedback Settings**를 비운다. 빠른 사라짐만 해제하고 이펙트·쉐이크 강화는 유지하려면 SO의 **Fade Immediately**만 끈다. 이미 발생한 사망·파티클·카메라 신호는 재생 시작 시 정한 설정으로 마무리된다.

## 변경 전후

| 항목 | 기존 동작·수치 | 임시 설정 |
| --- | --- | --- |
| 사망 페이드 시작 | 피격 반응과 Death 클립 종료 후. 공중에서는 착지 대기 | HP가 0 이하가 되는 프레임부터 시작. 공중에서도 즉시 시작 |
| 페이드 길이 | 마지막 그림을 유지하며 0.2초 | 0.10초. Death 클립을 시작하더라도 끝까지 기다리지 않고 동시에 페이드 |
| 최종 피격 반응 | 경직·넉백·점멸·펀치 스케일 종료까지 대기 | 최종 피격 이벤트 뒤 반응을 정리하고 바로 페이드. 행동 중단·콜라이더 해제·처치 확정도 즉시 처리 |
| 처치 수·코인 생성 | 피격 반응 완료 시 한 번 | 사망 프레임에 한 번 |
| 사망 혈흔 속도 | 6~9 유닛/초 + 위쪽 속도 0.5 | 전체 초기 속도 ×1.25. 기본 범위 7.5~11.25 + 위쪽 속도 0.625 |
| 사망 금속 파편 속도 | 6.5~9 유닛/초 + 위쪽 속도 0.5 | 전체 초기 속도 ×1.25. 기본 범위 8.125~11.25 + 위쪽 속도 0.625 |
| 사망 혈흔 개수 | 52~64개 | ×2로 104~128개 |
| 사망 금속 개수 | 8~16개 | ×2로 16~32개 |
| 일반 피격 쉐이크 강도 | 0.08 | 0.12, 기존 대비 ×1.5 |
| 크리티컬 피격 쉐이크 강도 | 0.18 | 0.27, 기존 대비 ×1.5 |
| 일반 처치 쉐이크 강도 | 0.08×3.2 = 0.256 | 0.256×1.5×1.6 = 0.6144, 기존 대비 ×2.4 |
| 크리티컬 처치 쉐이크 강도 | 0.18×3.2 = 0.576 | 1.3824, 기존 대비 ×2.4 |
| 일반 처치 쉐이크 길이 | 0.2×1.7 = 0.34초 | 0.544초, 기존 대비 ×1.6 |
| 크리티컬 처치 쉐이크 길이 | 0.26×1.7 = 0.442초 | 0.7072초, 기존 대비 ×1.6 |

위 쉐이크 값은 모듈의 기본 수치에 배율을 계산한 값이다. 최종 카메라 변위에는 기존 `EnemyHitCameraShakeManager.Intensity`, Listener Gain, 거리 감쇠가 적용된다. 매니저의 Intensity가 0이면 임시 모드에서도 흔들리지 않는다.

사망 버스트는 기존 360도 분사와 풀링을 재사용한다. 크기·중력·수명·표면 반응은 유지하고 개수와 초기 속도를 높였다. 개수 배율은 1~4 범위이며 이펙트 하나당 본체 입자는 최대 128개로 제한한다. 일반 피격 혈흔·금속 파편은 속도·개수 배율 1을 사용한다. 사망 이펙트는 적 밖에서 재생되어 몸체가 사라진 뒤에도 날아가고, 완료 후 풀로 돌아간다.

## 조정할 설정

| SO 필드 | 현재 값 | 용도 |
| --- | --- | --- |
| Use Temporary Feedback | 켜짐 | 임시 변경 전체를 켜거나 끈다 |
| Fade Immediately | 켜짐 | 사망 즉시 페이드할지 정한다 |
| Immediate Fade Duration | 0.10 | 즉시 페이드의 길이 |
| Burst Speed Multiplier | 1.25 | 사망 혈흔·금속 초기 속도 배율 |
| Burst Count Multiplier | 2 | 사망 혈흔·금속 개수 배율. 1~4, 본체 입자 최대 128개 |
| Hit Shake Strength Multiplier | 1.5 | 모든 적 피격 쉐이크 강도의 추가 배율 |
| Lethal Shake Strength Multiplier | 1.6 | 처치 타격에만 추가로 곱하는 강도 |
| Lethal Shake Duration Multiplier | 1.6 | 처치 타격에만 추가로 곱하는 지속 시간 |

## 조정 이력

2026-11-23 1차 설정은 페이드 0.08초, 사망 속도 ×1.8, 개수 ×1, 피격 쉐이크 ×1.25, 처치 추가 강도 ×1.6, 처치 추가 시간 ×1.25였다. 2차에서 페이드를 0.10초로 조금 늘리고 개수 ×2, 피격 쉐이크 ×1.5, 처치 추가 시간 ×1.6으로 변경했다. 속도와 처치 추가 강도는 유지했다. 1차 느낌으로 되돌릴 때는 이 값들을 SO에 입력하면 된다.

2026-11-23 추가 조정에서 사망 혈흔·금속의 속도 배율을 1.8에서 1.25로 낮췄다. 저장된 SO와 새 SO의 코드 기본값을 함께 변경했다. 초기 속도는 원래 이펙트 속도에 1.25를 곱하며, 이전 1.8에 다시 1.25를 곱하는 방식이 아니다.

Enemy18·20의 밝은 붉은 준비 파티클·가속·중심 도착 후 소멸은 [일반 수정](C:/Users/USER/BigAmberjack_Graduation-Project/Tools~/CTJ/AttackPreparationParticles.md)이다. Use Temporary Feedback 스위치는 해당 일반 수정에는 적용되지 않는다.

## 직접 테스트

1. `Assets/_Scenes/Test/EnemyTestScene.unity`를 실행하고 Enemy17 또는 Enemy18을 처치한다. 사망 즉시 몸체가 빠르게 투명해지고 혈흔은 강하게 사방으로 퍼져야 한다. 점프 중인 Enemy18도 착지 전에 사라져야 한다.
2. Enemy21 또는 Enemy22를 처치한다. 혈흔 대신 강화된 금속 파편이 튀고 몸체가 사라진 뒤에도 파편이 남아야 한다.
3. 일반 피격과 처치를 비교한다. 피격은 이전보다 약간 강하고 처치는 훨씬 강하게, 더 길게 흔들려야 한다. 플레이어 카메라의 기존 Cinemachine Impulse Listener를 사용한다.
4. 임시 SO의 Use Temporary Feedback을 끄고 새 적을 처치한다. 지상에서는 데스 애니메이션을 마친 뒤 0.2초 페이드, 공중에서는 착지 대기가 복구되어야 한다. 비교 후 켜기로 되돌린다. Play Mode에서 바꾼 값은 종료 시 되돌아간다.
5. 처치 수와 코인 보상이 한 번씩만 발생하는지 확인한다. 코인은 기존 회수 방식으로 골드가 지급된다.

## 확인 결과

- 컴파일 오류와 7종 프리팹의 끊어진 참조가 없는 것을 확인했다.
- 1차 EnemyTestScene 실행에서 7종 모두 공중에서 HP가 0이 된 프레임에 DeathStarted가 한 번 발생했다. 페이드 중 알파 감소를 확인했고 당시 0.08초 설정으로 약 0.089~0.096초 안에 적이 제거됐다.
- 처치 집계 7회와 각 적의 사망 보상 처리 1회를 확인했다. 중복 사망 호출에는 이벤트·집계·코인이 추가되지 않았다. 사망 버스트는 적 제거 뒤에도 남았다.
- 임시 설정이 꺼진 복제 SO로 기존 공중 착지 대기와 데스 애니메이션 후 페이드를 확인했다. 지상 Enemy17은 약 0.894초 뒤 제거되어 빠른 페이드와 구분됐다.
- 1차 설정 검증에서는 같은 난수 시드에서 혈흔과 금속의 모든 초기 속도가 정확히 ×1.8인 것을 확인했다. 0.12초간 비교한 수평 이동 범위는 각각 약 1.803배, 1.793배였다. 강화 후 풀에 반환한 인스턴스를 배율 1로 재사용하면 기존 속도가 복구됐다. 이 항목은 변경 전 속도 배율의 실행 기록이다.
- 2차 실행에서 혈흔 123개, 금속 28개가 재생되고 약 0.108~0.110초 뒤 적이 사라지는 것을 확인했다. 개수 배율 1·2·4와 상한, 같은 풀 인스턴스를 배율 1로 재사용했을 때 기존 개수로 복구되는 것을 확인했다.
- 2차 카메라 신호는 일반 피격 약 0.118125, 처치 약 0.6048, 처치 지속 시간 0.544초였다. 옵션 매니저 Intensity 0에서 신호가 생성되지 않는 것도 확인했다.
- 검증 후 저장된 EnemyTestScene의 Edit Mode로 복귀했다. 씬 파일은 수정하거나 저장하지 않았다.

## 사용한 문법과 이유

- `ScriptableObject`에 임시 설정을 모으고 `[SerializeField]`로 노출했다. 하나의 SO에서 7종을 함께 조정하고 전체 변경을 체크 하나로 복구할 수 있다.
- `조건 ? 값 : null`로 임시 모드가 꺼진 설정을 미연결 상태처럼 취급한다. 각 처리부가 기존 설정과 배율 1로 자연스럽게 돌아간다.
- `float speedMultiplier = 1f`, `float countMultiplier = 1f`는 선택적 매개변수다. 일반 피격·착탄 등 기존 호출은 인자를 생략해 원래 속도와 개수를 쓰고, 사망 버스트만 배율을 명시한다. 배율을 프리팹이나 풀 인스턴스의 저장 필드에 누적하지 않아 재사용 시 강화가 남지 않는다.
- `Mathf.RoundToInt`로 개수 배율을 정수에 적용하고 `Mathf.Clamp`로 최대 128개까지 제한한다. 필요할 때 파티클·흔적 배열을 확장하고 풀 재사용에서는 같은 배열을 계속 사용한다.
- 기존 UniTask 페이드에서 `Mathf.SmoothStep`으로 알파를 줄인다. 즉시 모드에서는 앞의 대기 구간을 건너뛰고 같은 페이드 처리로 진입한다. 사망 시작 때 모드와 시간을 저장해 재생 도중 SO를 바꿔도 현재 사망의 흐름이 뒤집히지 않도록 했다.
