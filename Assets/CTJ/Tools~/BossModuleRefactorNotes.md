# 보스 모듈 구성 수정 — 설정·문법·테스트

2026-10-20. 변경 범위는 Assets/CTJ입니다. 기존에 삭제된 설명 문서는 복원하지 않았고, 이번 변경만 이 문서에 기록합니다.

## 바뀐 설정

- `RobotEyeBoss/SkillModule`의 Skills 목록에 RadialVolley와 MovingLaser를 연결했습니다.
- 두 항목의 **Use Skill은 켜짐**, **Use For Automatic Selection은 꺼짐**입니다. 목록에 존재하되 일반 적의 거리 기반 자동 선택이 아니라 보스 FSM이 선택합니다.
- 지정 실행도 목록 포함 여부, Use Skill, 활성 컴포넌트, 공용 등록 여부, 쿨타임, 중복 실행을 검사합니다. 목록에서 빼거나 Use Skill을 끄면 실행할 수 없습니다. 실행 중 사용을 끄면 해당 스킬을 중단합니다.
- 일반 적의 Use For Automatic Selection은 켜져 있습니다. 기존 범위·높이·접지·시야·우선순위 조건을 그대로 사용합니다.
- `RobotEyeBoss/ArenaModule`이 중앙 앵커, 좌우 폭, 바닥까지 거리, 레이저 높이, 등장 높이를 가집니다. 기존 값(8, 4, 2.5, 4)은 유지했습니다.
- EnemyBase의 Legacy Attack 항목, attackInterval, attackRange, 별도 공격 타이머와 Attack 우회 경로를 제거했습니다. 세 프리팹에서도 해당 직렬화 값을 제거했습니다.
- 참조가 없던 EnemyPrototype 코드와 meta를 제거했습니다. Git에 있는 이전 버전으로 복구할 수 있습니다. 공격은 EnemySkillModule만 사용합니다.

## 거리 이탈과 공격 정리

이전에는 보스의 아레나 밖 플레이어를 유효하지 않은 타깃으로 취급하고, 공격 중단과 자기 탄 삭제를 같은 메서드에서 실행했습니다. 아레나와 타깃 유효성의 책임이 섞여 있던 것이 원인이었습니다.

| 상황 | 진행 중 패턴 | 이미 발사된 탄 |
| --- | --- | --- |
| 플레이어가 멀리 이동 | 계속 실행 | 비행·충돌·수명 유지 |
| 타깃 해제/교체/파괴/비활성화/사망 | 중단, 무적 해제 | 비행·충돌·수명 유지 |
| 보스 사망/비활성화 | 중단 | 자기 탄 정리 |
| HP 조건 특수 패턴 진입 | 일반 공격 중단, 특수 패턴 시작 | 이전에 합의한 자기 탄 정리 유지 |

아레나는 **보스 이동 목적지 제한과 레이저 위치 계산**에만 사용합니다. 플레이어를 아레나 밖으로 이동시켜도 원형 경고가 취소되거나 레이저 3회 횡단이 중단되지 않습니다. 일반 잡몹의 추적 해제 거리 규칙은 변경하지 않았습니다.

## SOLID 관점에서 나눈 책임

- `RobotEyeBoss`: 언제 어떤 패턴/스킬을 실행할지 결정.
- `BossArenaModule`: 공간 설정과 목적지 좌표 계산. 타깃 생존, 공격 취소, 투사체 삭제는 모름.
- `BossFlightModule`: 전달받은 목적지까지 이동.
- `EnemySkillModule`: 사용 가능한 목록 및 자동/지정 실행, 공용 쿨타임 경로 관리.
- `BossRadialVolleySkill`, `BossLaserSkill`: 각 공격의 경고와 피해 실행.
- `BossBase`: 보스 공통 타깃 유실·비활성화·무적과 자기 공격 정리의 생명주기.

이번에는 단일 책임 원칙(SRP)에 맞춰 실제로 분리할 책임을 나눴습니다. 필요 없는 인터페이스나 미래 보스용 추상 패턴 시스템을 추가하지 않았습니다. 기존 ModuleOwner의 모듈 초기화/조회 방식은 그대로 사용합니다.

## 사용한 문법과 이유

### 컴포지션과 Module 상속

`BossArenaModule : Module`을 자식 오브젝트에 붙였습니다. 보스 FSM이 설정 필드를 직접 가지는 대신 `GetModule<BossArenaModule>()`로 조합된 모듈을 가져옵니다. 공간 설정과 패턴 코드를 서로 다른 파일/컴포넌트에서 수정할 수 있습니다. ModuleOwner가 Initialize를 호출할 때 중앙 위치를 저장하므로, 보스가 이동해도 경기장의 중앙이 따라 움직이지 않습니다.

### 읽기 전용 프로퍼티

`Center { get; private set; }`, `FloorY => ...`, `LaserLeft => ...`를 사용했습니다. 설정 원본은 모듈이 관리하고, FSM에는 계산 결과만 제공합니다. 호출자가 중앙을 매 프레임 덮어쓰는 것을 방지합니다.

### bool로 선택 경로 구분

`useSkill`은 해당 스킬의 전체 사용 여부이고, `useForAutomaticSelection`은 일반 적 AI의 자동 후보 포함 여부입니다. 보스의 지정 스킬을 목록에서 지워 구분하는 대신, 두 개념을 명시적으로 구분했습니다. 자동 선택을 꺼도 지정 실행은 가능하지만, Use Skill을 끄면 둘 다 불가능합니다.

### Try 패턴과 out

`TryGetEnabledEntry(skill, out SkillEntry entry)`는 성공 여부와 찾은 항목을 함께 돌려줍니다. 지정 실행은 이 결과에서 Charge Duration을 읽습니다. 목록이 아닌 별도 인자로 같은 설정을 두 번 관리하지 않습니다.

`out _`는 찾은 항목 자체가 필요 없고 성공 여부만 필요한 경우입니다. `IsSkillEnabled`가 이 방식으로 구성 상태를 확인합니다. 쿨타임 때문에 잠시 기다려야 하는 경우와 사용 해제된 스킬을 구분하므로, 해제된 패턴을 영원히 기다리거나 무적이 남지 않게 합니다.

### 중단과 삭제 분리

`InterruptPattern()`은 현재 스킬과 이동을 멈추고 무적을 해제합니다. `ClearProjectiles()`는 생성한 탄 목록만 정리합니다. 전자는 실제 타깃 유실에도 쓰고, 후자는 사망·비활성화·명시적 페이즈 전환에서만 호출합니다. 여러 의미를 가진 하나의 포괄적인 정리 함수를 피했습니다.

## 직접 테스트

1. `Assets/CTJ/Prototypes/Bosses/BossPatternTest.unity`를 열어 Play합니다. A/D 또는 방향키로 더미 이동, Space로 점프합니다.
2. 보스 프리팹의 SkillModule에 스킬 두 개가 표시되고, 루트에는 Legacy Attack이나 아레나 설정이 없는지 확인합니다. 아레나 설정은 ArenaModule에 있습니다.
3. 원형 경고가 뜨면 더미를 멀리 옮깁니다. 필요하면 Scene 뷰에서 TestTarget의 x를 50으로 옮겨 확실히 영역 밖으로 보냅니다. 경고 위치는 고정되어 있고 탄은 발사되어야 합니다. 탄이 비행 중일 때 멀어져도 탄이 동시에 삭제되면 안 됩니다.
4. HP 2500에서 `Deal 1500 damage`를 누릅니다. 레이저 경고 중 더미를 멀리 옮겨도 편도 3회를 마친 뒤 중앙 복귀·무적 해제가 이루어져야 합니다.
5. Play 중 SkillModule의 RadialVolley 항목에서 Use Skill을 끄면 새 탄막을 시작하지 않아야 합니다. MovingLaser를 끈 상태에서 HP를 1000 이하로 낮춰도 사용할 수 없는 패턴을 기다리며 무적이 남으면 안 됩니다. Stop하면 이 임시 조작은 원복됩니다.
6. 실제 타깃을 해제하면 진행 중 스킬은 중단하되 발사된 탄은 수명대로 남는지, 보스를 비활성화하면 자기 탄이 정리되는지 확인합니다.

### 검증 도구

`VerifyRobotEyeBoss.ValidatePrefab`은 모듈 7개, 목록 2개, 누락 참조 및 레거시 필드 제거를 검사합니다. `Begin → Run → Stop → Restore`는 독립 씬에서 보스 테스트를 수행하고 원래 시작 씬을 복원합니다. 저장되지 않은 사용자 씬이 있으면 Begin은 중단합니다.

자동 검증에는 거리 이탈 중 경고 완료, 12발 유지·이동·자연 소멸, 먼 타깃 상태의 레이저 3회 완주, 목록 제거/사용 해제, 고속 빔, 플레이어 공격 Caster의 피해 전달을 포함합니다. 실제 던전 전체의 난이도나 회피 체감을 검증했다는 의미는 아닙니다.

최종 결과: Unity 재컴파일 오류 0건, 프리팹 참조 검사 통과, 보스 런타임 검사 59개 통과, 기존 잡몹 회귀 시나리오 90개 통과, 최종 Play Console 오류 0건. 재화 예외 테스트의 예상 경고 3건은 정상 결과입니다. 테스트 후 원래 시작 씬과 CTJ_MapTestScene 편집 상태를 복원했습니다.
