# 선택적 상하 반전 모듈

2026-10-29. Assets/CTJ 안에서만 수정했습니다.

## 설정과 동작

현재 반전을 연결한 적은 `Enemy02_ProjectileRobot`입니다. 루트 아래에 `VerticalFlipModule` 자식 오브젝트를 추가하고 `EnemyVerticalFlipModule` 컴포넌트 체크는 기본적으로 껐습니다. 다른 적 프리팹에는 추가하지 않았습니다.

1. Enemy02 인스턴스를 천장에 배치합니다. **적 루트의 Y 위치가 천장 아랫면**이 되게 맞춥니다. 루트 Scale은 원래 값을 유지합니다.
2. 자식 `VerticalFlipModule`을 선택합니다. 오브젝트는 활성 상태를 유지하고 **Enemy Vertical Flip Module 컴포넌트 왼쪽 체크**를 켭니다.
3. Play 하면 몸통·런처·마스크·피격 콜라이더가 루트를 기준으로 상하 반전됩니다. 대기 위치에서 아래로 전개하고, 수납할 때는 포신을 위쪽 천장 안으로 접고 함께 올라갑니다.
4. 체크를 끄면 원래 방향으로 돌아옵니다. 천장 위치는 자동으로 찾거나 이동하지 않으므로, 바닥용으로 바꿀 때는 루트 위치도 직접 바닥에 맞춥니다.

편집 모드에서는 체크 설정만 저장하며 외형 반전은 Play에서 적용합니다. 실행 중에는 체크 변경이 즉시 적용됩니다. 같은 값을 반복 지정해도 계속 뒤집히지 않습니다. 모듈 오브젝트/적을 비활성화하면 원래 Y 스케일로 돌려놓고, 다시 활성화하면 컴포넌트 설정을 적용합니다.

**루트의 Y 스케일 부호만 바꿉니다.** X/Z 스케일, 위치, 기존 전개 시간과 회전 속도는 유지합니다. 천장에 고정되는 Enemy02를 대상으로 연결했으며, 일반 보행 적의 중력이나 천장 이동 기능을 추가한 것은 아닙니다.

조준 방향과 조준선은 실제 반전된 총구 방향에 맞춥니다. 체력 UI는 적 아래로 위치를 옮기되 글자/게이지 방향은 뒤집지 않습니다. 처치 코인의 생성 오프셋 Y도 뒤집어 천장 아래에서 생성하며, 코인의 중력과 지급 규칙은 유지합니다.

실행 중 반전을 바꾸는 순간 진행 중인 공격은 정리합니다. 반전 전 고정한 방향과 반전 후 총구가 어긋난 상태로 발사되는 것을 막기 위한 처리입니다. 이미 발사되어 적과 독립적으로 움직이는 탄환에는 영향을 주지 않습니다.

## 코드에서 사용

적의 Awake/모듈 초기화가 끝난 뒤 사용합니다. 예를 들어 Instantiate한 적을 설정하거나, 다른 컴포넌트의 Start에서 호출할 수 있습니다.

```csharp
using CTJ.Enemies;

EnemyVerticalFlipModule flip = enemy.GetModule<EnemyVerticalFlipModule>();
if (flip != null)
{
    flip.SetFlipped(true);  // 천장 방향. 컴포넌트 enabled = true와 같음
    // flip.SetFlipped(false); // 원래 방향
    bool currentlyFlipped = flip.IsFlipped;
}
```

공용 ModuleOwner는 비활성 모듈도 초기화/등록하므로 기본 체크가 꺼져 있어도 GetModule로 가져올 수 있습니다. 오브젝트 자체를 비활성화해 두면 컴포넌트 enabled만 켜도 동작하지 않으므로, 기본 프리팹처럼 모듈 오브젝트를 켜 두고 컴포넌트 체크로 제어하세요. 새 모듈은 생성 전에 적 자식으로 구성해야 하며, 초기화가 끝난 적에 런타임 AddComponent로 등록하는 기능은 추가하지 않았습니다.

## 직접 테스트하는 순서

1. CTJ_MapTestScene에 Enemy02 두 개를 배치합니다. 하나는 바닥에 기본 상태, 다른 하나는 천장 아랫면에 놓고 반전 모듈 체크를 켭니다. 두 적을 너무 가까이 겹치지 않게 둡니다.
2. Play 후 천장 터렛의 공격 범위 안으로 들어갑니다. 몸통이 아래로 나오고 런처가 플레이어 쪽으로 부드럽게 회전하는지 확인합니다.
3. 플레이어를 터렛의 왼쪽 아래와 오른쪽 아래로 이동시킵니다. 조준선과 총구가 같은 방향을 향하고 실제 탄환도 그 방향으로 날아가는지 확인합니다.
4. 범위 밖으로 나가면 런처가 위로 접힌 뒤 몸통과 함께 천장 안으로 들어가는지 확인합니다. 바닥 터렛은 기존처럼 아래로 접히고 내려가야 합니다.
5. Play 중 모듈 체크를 껐다 켜 봅니다. 위치/X 스케일은 그대로이며 상하만 바뀌고, 중복으로 켜도 다시 뒤집히지 않아야 합니다.
6. 체력 UI를 붙여 두었다면 천장 터렛 아래에 바가 똑바로 보이는지 확인합니다. 적을 처치하면 코인이 천장 아래에서 나오고, CurrencyManager가 있는 환경에서는 소멸 후 기존 총액이 지급되는지 확인합니다.

이번 검증: Unity 컴파일 오류 0건, 프리팹 Missing Script 없음, Enemy02에만 모듈 연결/기본 비활성 확인. 독립 Play 씬에서 시작 전 활성화·API/체크/자식 활성 토글·좌우 아래 목표 피격·피격 영역 반전·공격 취소·전개/수납·조준선/총구 일치·UI 방향·코인 5개/15골드 지연 지급을 통과했습니다. 기존 바닥 터렛의 전개·조준·발사·수납·지형 차단·사망 후 탄환 유지 테스트도 통과했습니다. 실제 렌더링으로 수납 마스크와 외곽선을 비교했고, 원래 사용자 씬을 저장하지 않고 복구했습니다.

검증 도구는 `VerifyEnemyVerticalFlip.RunEdit / RunPlay`입니다. 기존 `VerifyEnemy01.BeginPlay → RunPlay → StopPlay → RestoreScene` 절차로 저장된 씬을 보존한 독립 씬에서 실행합니다. `RenderPreview`는 필요할 때만 PNG를 만들며 확인 후 제거할 수 있습니다.

## 사용한 문법과 이유

- **기존 Module 상속과 IAfterInitModule 구현**: 프로젝트의 모듈 검색/초기화 규칙을 그대로 사용합니다. 모든 모듈의 Initialize가 끝난 AfterInit에서 반전을 적용해 스킬 모듈이 준비되기 전에 접근하지 않게 합니다. 새 인터페이스는 만들지 않았습니다.
- **OnEnable / OnDisable / enabled**: Unity 컴포넌트 체크 자체를 설정으로 사용합니다. 별도 bool과 체크 상태가 서로 다른 두 가지 설정이 되지 않도록 SetFlipped도 enabled에 위임합니다. Reset은 에디터에서 처음 추가할 때 기본 체크를 끕니다.
- **`public bool IsFlipped { get; private set; }`**: 외부에서 현재 적용 상태를 읽되 임의로 상태값만 바꾸지 못하게 하는 프로퍼티입니다. 실제 변경은 SetFlipped를 거칩니다.
- **원래 스케일 저장 + 가드 조건**: 최초 Y 값을 기억한 뒤 그 값에 -1 또는 1을 곱합니다. 현재 Y를 매번 뒤집는 방식과 달리 반복 호출/재활성화에도 크기가 누적되지 않습니다. 상태가 같으면 즉시 return합니다.
- **`localRotation` / `InverseTransformVector` / `TransformVector`**: 목표 방향은 월드 좌표이고 런처 회전은 부모 기준 좌표입니다. 목표 벡터를 부모 공간으로 바꿔 로컬 회전을 계산하고, 발사 방향은 실제 로컬 +X 축을 월드로 변환합니다. Transform.right는 회전 기반 방향이어서 음수 스케일 반전을 그대로 표현하지 못하므로 TransformVector를 사용했습니다.
- **`Mathf.Atan2`와 Quaternion.Euler**: 로컬 방향 벡터를 Z 회전각으로 바꿉니다. 기존 SmoothDampAngle과 최대 회전 속도 제한은 유지합니다.
- **UI 축의 부호 있는 스케일 보정**: 반전 부모 아래에서는 월드 rotation만 지정해도 실제 사각형 축이 거꾸로 기울 수 있습니다. 원하는 가로/세로 방향을 부모 공간으로 옮겨 조준선의 회전과 크기를 같이 보정합니다. 체력 UI는 별도로 반전 스케일을 상쇄해 읽는 방향을 유지합니다.
