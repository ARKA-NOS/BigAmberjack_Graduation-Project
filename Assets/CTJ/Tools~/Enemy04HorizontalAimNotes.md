# Enemy04 — 수평 사격과 정방향 거리 확보

2026-10-28. 변경은 Assets/CTJ 안에서만 진행했습니다.

## 변경 동작

- 준비 중 플레이어가 있는 좌우 방향으로 돌아보되, 높이를 따라 위아래로 조준하지 않습니다. 조준선과 화살은 FirePoint 높이에서 수평으로 나갑니다.
- 너무 가까워지면 플레이어 반대쪽으로 몸을 돌려 기존 Move 애니메이션으로 뛰어갑니다. 뒤로 걷지 않습니다.
- 기존 최소 거리 5m를 확보하면 정지하고 다시 플레이어 쪽으로 돌아봅니다. 쿨타임이 남아 있어도 공격 가능한 위치에서는 플레이어를 바라보며 기다립니다.
- 원래 범위인 5~11m, 이동 속도 3.2, 준비 0.8초, 마지막 조준 고정 0.15초, 후딜 0.6초, 쿨타임 2.8초, 피해량 14는 유지했습니다. 발사 직전 방향 고정 이후 플레이어가 반대편으로 넘어가도 이번 화살은 고정된 방향으로 나갑니다.
- 거리 계산은 기존처럼 루트 사이 2D 거리입니다. 높이가 다른 플레이어를 향해서도 수평 발사하므로 화살 궤도와 겹치지 않으면 빗나갑니다.
- 후속 버그 수정: 5~11m 안에서는 위·아래 발판으로 시야가 막혀 공격하지 못하더라도 접근/후퇴를 반복하지 않고 멈춰 기다립니다. 시야가 열리면 기존 FSM이 사격을 재개합니다.

## 구조와 인스펙터

`SkillModule/ProjectileAttack → EnemyProjectileSkill → Horizontal Aim Only`를 추가해 04에만 켰습니다. 기본값은 꺼짐이므로 MadGhost와 Enemy02는 기존 위치 조준을 사용합니다. `Face Target During Preparation`과 `Track Target During Preparation`은 기존대로 켜져 있으며, 이 조합에서는 좌우를 추적합니다.

`EnemyKeepDistanceModule`은 이전에 이동 후 `FaceTarget()`을 호출하여 계속 플레이어를 바라봤습니다. 이제 기존 이동 함수에서 받은 방향(-1 / 0 / +1)을 반환하고, `EnemyBase`가 그 방향으로 비주얼을 돌립니다. 사거리 안에 들어오면 기존 `ExecuteAttack()`에서 타깃을 다시 바라봅니다. 별도 FSM·이동 애니메이션·모듈을 추가하지 않았습니다.

수평 방향은 발사 위치가 아닌 **적 루트와 타깃 루트의 X 차이**로 정합니다. 가까운 타깃이 몸체와 활 사이에 있을 때 화살만 몸체 반대쪽으로 나가는 것을 피하기 위함입니다. X가 정확히 같으면 현재 바라보는 방향을 유지합니다.

이번에 수정한 런타임 파일은 `EnemyBase.cs`, `EnemyKeepDistanceModule.cs`, `Skills/EnemyProjectileSkill.cs`와 `Enemy04_MechanicArcher.prefab`입니다. 테스트 코드와 생성 도구에도 새 동작을 반영했습니다. 사용자 변경이 있던 Enemy01 프리팹과 CTJ_MapTestScene은 수정하지 않았습니다.

## 직접 테스트

1. CTJ_MapTestScene을 Play하고 Enemy04와 플레이어를 기존 방식으로 연결합니다.
2. 적의 오른쪽에서 5m보다 가까이 접근합니다. 적이 왼쪽으로 돌아 정방향으로 뛰어가고, 5m를 확보하면 정지한 뒤 오른쪽으로 돌아 조준하는지 확인합니다.
3. 왼쪽에서도 반복합니다. 이번에는 오른쪽으로 달아났다가 다시 왼쪽을 보고 조준해야 합니다.
4. 사거리 안에서 점프하거나 높이가 다른 발판으로 이동합니다. 조준선과 화살은 계속 수평이어야 합니다. 화살 높이를 벗어나면 맞지 않습니다.
5. 준비 중 반대편으로 넘어가면 좌우 조준이 전환되는지 확인합니다. 단, 마지막 0.15초 조준 고정이 시작된 뒤에는 방향을 유지하는 것이 정상입니다.
6. 벽이나 낭떠러지를 등지고 가까이 접근합니다. 적이 거리 확보를 위해 벽을 뚫거나 낭떠러지로 뛰어들지 않고 멈추는지 확인합니다.

## 사용 문법과 선택 이유 — 학습용

### bool 옵션과 SerializeField

`[SerializeField] private bool horizontalAimOnly;`로 인스펙터에서 저장 가능한 선택지를 만들었습니다. bool 기본값은 false이므로 기존 적은 그대로 동작하고 04만 켤 수 있습니다. 두 가지 방식이면 충분하므로 enum이나 별도 추상 클래스를 추가하지 않았습니다.

### 방향 벡터와 Mathf.Sign

`Mathf.Sign(offsetX)`는 오른쪽이면 +1, 왼쪽이면 -1을 줍니다. `Vector2.right * side`는 `(1, 0)` 또는 `(-1, 0)`이므로 방향의 Y가 항상 0입니다. 이 하나의 방향을 기존 조준선과 발사체가 함께 사용하여 표시와 실제 발사를 일치시킵니다.

### 반환값과 책임 분리

거리 확보 함수의 반환형을 `void`에서 `float`로 바꿨습니다. 이동 함수가 이미 계산한 방향을 돌려주고, 몸체 반전은 기존 `EnemyBase.OnMoveDirectionChanged()`에 맡깁니다. 같은 값을 다시 계산하거나 프레임마다 이동 모듈과 공격 모듈이 서로 방향을 덮어쓰지 않도록 하기 위함입니다. 벽 등으로 움직이지 않으면 0을 반환하여 불필요한 반전을 하지 않습니다.

### internal 읽기 전용 프로퍼티와 조건 연산자

`internal float FacingDirection => ...;`는 같은 어셈블리의 스킬이 현재 방향을 읽기 위한 프로퍼티입니다. 외부에서 방향 값을 직접 변경할 수 없고, 인스펙터 저장값도 하나 더 만들지 않습니다.

`조건 ? A : B`는 짧은 분기인 조건 연산자입니다. X 차이가 사실상 0이면 현재 방향을 유지하고, 그렇지 않으면 플레이어가 있는 쪽을 선택합니다. `Mathf.Approximately`는 부동소수점 값을 단순히 `== 0`으로 비교할 때 생길 수 있는 작은 오차를 고려합니다.

## 후속 버그: 다른 발판에 있는 플레이어를 보며 좌우로 떨림

사용자가 제공한 GIF는 달리는 도중 방향을 계속 바꾸는 모습이었습니다. 서로 다른 발판에서 바닥이 시야를 가리는 조건으로 재현했고, 수정 전에는 2초 동안 97~98번 방향을 바꾸며 약 0.129m 안에서 왕복했습니다.

원인은 공격 가능 여부와 거리 확보를 같은 조건처럼 다룬 데 있었습니다. FSM은 시야가 막히면 공격하지 못해 Chase에 남습니다. 거리 모듈은 최소 거리 5m 이상이면 다시 접근하고, 5m 안에 들어오면 후퇴했습니다. 시야를 가린 발판은 계속 남아 있으므로 이 두 행동이 물리 프레임마다 반복되었습니다. 이전의 높이 차이 테스트는 시야가 열린 배치였고, 발판으로 시야가 가려지는 조건을 놓쳤습니다.

`EnemyKeepDistanceModule.MoveTowardsTarget()`에 적정 거리에서 정지하는 분기를 추가했습니다. 이동은 가까움 / 적정 거리 / 멂의 세 경우로 결정하고, 실제 발사는 기존 FSM의 시야·쿨타임 검사에 맡깁니다. 따라서 거리를 맞춘 뒤 시야가 막혀 있으면 플레이어를 바라보며 기다립니다. 점프나 다른 발판으로 가는 경로 탐색은 추가하지 않았습니다.

수정 후 위·아래 두 배치에서 초기 착지와 거리 보정이 끝난 뒤 2초 동안 방향 전환 0회, 수평 이동 0을 확인했습니다. 가까운 타깃에게서 후퇴한 뒤 정지, 먼 타깃에게 접근한 뒤 정지, 같은 발판으로 이동한 타깃을 다시 공격하는 것도 통과했습니다. 기존 수평 사격·좌우 정방향 후퇴·피격 취소·벽/낭떠러지 정지 테스트도 통과했습니다. Unity 컴파일 오류는 없었습니다.

검증 코드는 `VerifyEnemy04RangeStability.RunPlay`입니다. 직접 확인하려면 Enemy04와 플레이어를 서로 다른 발판에 놓고, 루트 사이 거리를 약 5m로 맞춥니다. 이제 좌우로 계속 뒤집히지 않고 정지해야 합니다. 이어 같은 발판으로 돌아와 사거리 안에 서면 수평 사격을 재개해야 합니다.

추가로 사용한 문법은 `offset.sqrMagnitude`와 조기 `return`입니다. `sqrMagnitude`는 거리의 제곱이므로 최소·최대 거리도 각각 제곱하여 비교합니다. 제곱근을 구하지 않고 범위 포함 여부를 확인할 수 있습니다. 적정 거리라면 `Stop()`과 `FaceTarget()` 후 `return 0f`로 끝내서, 아래쪽 접근/후퇴 코드가 실행되지 않도록 했습니다.
